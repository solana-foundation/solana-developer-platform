Treasury uses the [Earn integration guide](/docs/earn/integration-details). It has no separate yield
endpoints or program-allocation model.

With an SDP API key, use `source: { "ownerAddress": "<owner-public-key>" }` and
your preferred compatible Solana wallet. Sign the returned transaction through
your integration, then submit its exact signed bytes. No SDP wallet record or
provider connection is required.

An existing connected wallet's `walletId` is an optional convenience. It keeps
its signing and fee policies while the worker requests its provider signature.
Both sources use the same asynchronous operation flow.

Discovery, position reads, operation history and withdrawals use the shared
contract. Signing progress survives the request and browser session. Once
`/submit` is accepted, refresh and cancellation are unavailable; track the same
operation through signing and settlement. Only a known terminal failure permits
a new deposit or withdrawal with a new idempotency key.
