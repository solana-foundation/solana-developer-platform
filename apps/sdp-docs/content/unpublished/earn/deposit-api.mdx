Deposit into a strategy, then see your position. This example uses the
strategy's native token; your wallet pays the transaction fees.

## Before you start

- A sandbox project with an API key granting `earn.execute` (includes read).
- A connected Kit wallet signer, devnet SOL, and the strategy's test deposit token.
- `curl` and `jq`, or Node.js for the TypeScript backend examples.

Keep the key on your backend. Sandbox uses devnet. For TypeScript, save the
[HTTP request helper](/docs/earn/quickstart?integration=earn-api#typescript-request-helper) as server-only `earn-api.ts`;
the examples below import it.

## 1. Choose a strategy

Set `SDP_API_KEY` in your backend environment. For cURL, also set
`OWNER_ADDRESS` in your terminal.

<Tabs items={["cURL", "TypeScript"]} groupId="earn-code-language">
<Tab value="cURL">

```bash
export SDP_API_URL="https://api.solana.com"

curl --fail-with-body -sS "$SDP_API_URL/v1/earn/strategies?pageSize=100" \
  -H "Authorization: Bearer $SDP_API_KEY" \
  > strategies.json

jq '.data.strategies[] | select(
  .hostCluster == "devnet" and
  .fundable and .status == "active" and .depositSlippage == null
) | {id, name, depositMint: .depositMints[0]}' strategies.json
```

</Tab>
<Tab value="TypeScript">

```typescript
import { earnRequest } from "./earn-api";

type Strategy = {
  id: string;
  name: string;
  hostCluster: string;
  fundable: boolean;
  status: string;
  depositSlippage: unknown;
  depositMints: string[];
};
const catalogue = await earnRequest("/v1/earn/strategies?pageSize=100");
const strategies: Strategy[] = catalogue.data.strategies;
console.table(strategies.filter((strategy) =>
  strategy.hostCluster === "devnet" &&
  strategy.fundable && strategy.status === "active" && strategy.depositSlippage === null
).map(({ id, name, depositMints }) => ({ id, name, depositMint: depositMints[0] })));
```

</Tab>
</Tabs>

Set `STRATEGY_ID` to a returned ID and fund your wallet with its `depositMint`.
Set `AMOUNT` to a decimal token amount, such as `"25"`.
Run the TypeScript examples in order in one backend module.

No rows? Follow the catalogue's pagination or arrange sandbox access. A mirrored
mainnet strategy cannot accept test funds; changing the cluster query will not
enable it. See [strategy availability](/docs/earn/providers#check-availability).

## 2. Make the deposit

Follow **Preview**, **Build**, **Sign**, then **Submit**. Run API requests on your
backend; only signing happens in the customer's wallet. Sign without
broadcasting or changing the transaction, then submit promptly through SDP.

<Tabs items={["Preview", "Build", "Sign", "Submit"]}>
<Tab value="Preview">

### Preview the deposit

Check the expected shares before building. Resolve every `blockingIssues`
entry, even after HTTP 200.

<Tabs items={["cURL", "TypeScript"]} groupId="earn-code-language">
<Tab value="cURL">

```bash
curl --fail-with-body -sS "$SDP_API_URL/v1/earn/vault-deposit-previews" \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -nc --arg strategyId "$STRATEGY_ID" --arg amount "$AMOUNT" \
    '{strategyId: $strategyId, amount: $amount}')" \
  > preview.json

jq '.data | {sharesOut, shareDecimals, blockingIssues}' preview.json
```

</Tab>
<Tab value="TypeScript">

```typescript
const STRATEGY_ID = "<ID selected from step 1>";
const AMOUNT = "25";
const { data: preview } = await earnRequest(
  "/v1/earn/vault-deposit-previews",
  JSON.stringify({ strategyId: STRATEGY_ID, amount: AMOUNT }),
);
if (preview.blockingIssues.length > 0) {
  console.log(preview.blockingIssues);
  throw new Error("Resolve the preview blockers before building");
}
console.log({ sharesOut: preview.sharesOut, shareDecimals: preview.shareDecimals });
```

</Tab>
</Tabs>

This example selects strategies with `depositSlippage: null` and omits
`minSharesOut`. For strategies that require a share floor, follow their live
[quote-protection policy](/docs/earn/integration-details#quote-protection).

</Tab>
<Tab value="Build">

### Build the transaction

Build an unsigned transaction. This moves no funds.

<Tabs items={["cURL", "TypeScript"]} groupId="earn-code-language">
<Tab value="cURL">

```bash
curl --fail-with-body -sS "$SDP_API_URL/v1/earn/external-wallet/deposit-transactions" \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -nc --arg strategyId "$STRATEGY_ID" \
    --arg ownerAddress "$OWNER_ADDRESS" --arg amount "$AMOUNT" \
    '{strategyId: $strategyId, ownerAddress: $ownerAddress, amount: $amount}')" \
  > build.json

jq '.data.transaction | {transactionId, lastValidBlockHeight}' build.json
```

</Tab>
<Tab value="TypeScript">

```typescript
const OWNER_ADDRESS = "<customer wallet public key>";
const { data: build } = await earnRequest(
  "/v1/earn/external-wallet/deposit-transactions",
  JSON.stringify({ strategyId: STRATEGY_ID, ownerAddress: OWNER_ADDRESS, amount: AMOUNT }),
);
const built = build.transaction;
console.log(built);
```

</Tab>
</Tabs>

Keep `data.transaction.transactionId` with the unsigned base64 bytes at
`data.transaction.transaction`.

</Tab>
<Tab value="Sign">

### Sign with your wallet

Send the unsigned bytes to the customer's wallet. With a Kit wallet signer:

<Tabs items={["TypeScript"]}>
<Tab value="TypeScript">

```typescript
import {
  getBase64EncodedWireTransaction,
  getBase64Encoder,
  getTransactionDecoder,
} from "@solana/kit";

const unsigned = getTransactionDecoder().decode(
  getBase64Encoder().encode(built.transaction),
);
const [signed] = await walletSigner.modifyAndSignTransactions([unsigned]);
if (!signed) throw new Error("The wallet returned no signed transaction");
const signedTransaction = getBase64EncodedWireTransaction(signed);
```

</Tab>
</Tabs>

`built` is `data.transaction` from Build; `walletSigner` is the customer's
signer. Return the signed bytes to your backend and set `SIGNED_TRANSACTION`.

</Tab>
<Tab value="Submit">

### Submit the transaction

Save one UUIDv4 key with the exact signed body before sending. For cURL, set
`IDEMPOTENCY_KEY` once. The first section below saves it in `submission.key`
beside `submission.json`; retries start at the saved-key read.

<Tabs items={["cURL", "TypeScript"]} groupId="earn-code-language">
<Tab value="cURL">

```bash
# First send only: save the body and key before submitting.
TRANSACTION_ID=$(jq -er '.data.transaction.transactionId' build.json)

jq -nc --arg transactionId "$TRANSACTION_ID" \
  --arg signedTransaction "$SIGNED_TRANSACTION" \
  '{transactionId: $transactionId, signedTransaction: $signedTransaction}' \
  > submission.json
printf '%s\n' "$IDEMPOTENCY_KEY" > submission.key

# First send and every retry start from these saved files.
IDEMPOTENCY_KEY=$(cat submission.key)

curl --fail-with-body -sS "$SDP_API_URL/v1/earn/external-wallet/deposits" \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  --data-binary @submission.json \
  > deposit.json

jq '.data.deposit | {movementId, positionId, status, signature}' deposit.json
```

</Tab>
<Tab value="TypeScript">

```typescript
import { randomUUID } from "node:crypto";
import { readFile, writeFile } from "node:fs/promises";

const SIGNED_TRANSACTION = "<base64 signed bytes returned by the customer's wallet>";
const intent = {
  key: randomUUID(),
  body: JSON.stringify({
    transactionId: built.transactionId,
    signedTransaction: SIGNED_TRANSACTION,
  }),
};
// Create once. Refuse to overwrite an existing intent.
await writeFile("earn-deposit-intent.json", JSON.stringify(intent), {
  flag: "wx", mode: 0o600, flush: true,
});

// First send and every retry: load the same saved body and key.
const saved = JSON.parse(await readFile("earn-deposit-intent.json", "utf8"));
const { data: { deposit } } = await earnRequest(
  "/v1/earn/external-wallet/deposits", saved.body, saved.key,
);
console.log(deposit);
```

</Tab>
</Tabs>

</Tab>
</Tabs>

If the response is uncertain, retry the same saved body and key. A signature
or expired blockhash does not prove failure; resolve the original before
replacing it. In TypeScript, restart at the saved-intent read; never recreate
the file or key for a retry.

## 3. See your position

Poll the movement until `finalized` or `failed`, then refresh positions.
Your app may show confirmation sooner while reconciliation continues.

<Tabs items={["cURL", "TypeScript"]} groupId="earn-code-language">
<Tab value="cURL">

```bash
MOVEMENT_ID=$(jq -er '.data.deposit.movementId' deposit.json)

curl --fail-with-body -sS \
  "$SDP_API_URL/v1/earn/external-wallet/movements/$MOVEMENT_ID" \
  -H "Authorization: Bearer $SDP_API_KEY"

curl --fail-with-body -sS --get \
  "$SDP_API_URL/v1/earn/external-wallet/positions" \
  -H "Authorization: Bearer $SDP_API_KEY" \
  --data-urlencode "ownerAddress=$OWNER_ADDRESS"
```

</Tab>
<Tab value="TypeScript">

```typescript
const movement = await earnRequest(
  `/v1/earn/external-wallet/movements/${encodeURIComponent(deposit.movementId)}`,
);
console.log(movement.data.movement);

const query = new URLSearchParams({ ownerAddress: OWNER_ADDRESS });
const positions = await earnRequest(`/v1/earn/external-wallet/positions?${query}`);
console.log(positions.data.positions);
```

</Tab>
</Tabs>

At `finalized`, your wallet holds the strategy's shares. Keep unavailable position
fields distinct from zero. See [balances and earnings](/docs/earn/reporting)
for settlement states and pagination.
