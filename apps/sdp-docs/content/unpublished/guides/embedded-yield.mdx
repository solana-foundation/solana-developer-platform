Your backend builds a transaction through SDP. The customer's wallet signs it
in your app, then your backend sends it to SDP for tracking and broadcast.
The customer owns the position; SDP holds no key for their wallet.

Start with the [quickstart](/docs/earn/quickstart), or read
[positions and shares](/docs/earn/concepts) for the core concepts.

## Authenticate on your backend

Keep your project's API key on your backend.

| Grant | Allows |
| --- | --- |
| `earn.read` | Discovery, previews, and reads. |
| `earn.execute` | Transaction builds and submits, plus read. |
| `earn.manage` | Withdrawal cancellation builds, plus read. |

Execute and manage do not imply each other.

- Authenticate each customer and check wallet access. The key can read all
  customer positions recorded by your project.
- Custody-wallet scope does not restrict customer-owned wallets. The owner's
  signature authorizes each transaction.

## Get the backend module

1. Open [Embedded Yield → Integrate](https://platform.solana.com/dashboard?return_to=%2Fdashboard%2Fmarkets%2Fembedded-yield%2Fconfigure)
   and select your project and environment.
2. Choose a strategy. It must be active and fundable.
3. Click **Copy all code** above the code sections. Paste the complete module
   into a server-only `earn.ts` file and set `SDP_API_KEY` on your backend.

The button copies every section, including deposit, portfolio, and withdrawal
helpers. Keep the module and key off browsers and mobile apps. For individual
requests, use [Deposit with the API](/docs/earn/deposit-api).

## Make a deposit

| Step | Request or action |
| --- | --- |
| 1. Choose a strategy | [`GET /v1/earn/strategies`](/docs/reference/api/earn/list-earn-strategies). |
| 2. Preview | [`POST /v1/earn/vault-deposit-previews`](/docs/reference/api/earn/create-earn-vault-deposit-preview). |
| 3. Build | [`POST /v1/earn/external-wallet/deposit-transactions`](/docs/reference/api/earn/create-earn-external-wallet-deposit-transaction). |
| 4. Sign | The customer's wallet signs the returned base64 transaction. |
| 5. Submit | [`POST /v1/earn/external-wallet/deposits`](/docs/reference/api/earn/create-earn-external-wallet-deposit) with an `Idempotency-Key`. |

Build with `strategyId`, `ownerAddress`, decimal-string `amount`, and
`minSharesOut` when the strategy requires
[quote protection](/docs/earn/integration-details#quote-protection). Submission
takes the returned `transactionId` and `signedTransaction`.

- Sign without broadcasting or changing SDP's message.
- Persist the key and exact signed body before submitting. Submit promptly
  through SDP, which records the signed intent before broadcast.
- After an uncertain response, retry both unchanged. See
  [retry safely](/docs/earn/integration-details#retry-safely).

Save the returned `movementId` and [poll the movement](/docs/reference/api/earn/get-earn-external-wallet-movement). Follow
[positions and activity](/docs/earn/reporting) for confirmation and settlement.

## Withdraw and restore activity

1. Read live `withdrawableShares` and [withdrawal options](/docs/reference/api/earn/get-earn-external-wallet-withdrawal-options).
2. For a direct exit, [preview](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-preview)
   where supported, [build](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-transaction),
   sign, and [submit](/docs/reference/api/earn/create-earn-external-wallet-withdrawal).
3. Restore outstanding requests after restart. Follow
   [Withdrawals](/docs/earn/withdrawals) for asynchronous exits.

Withdrawals spend shares, not a requested dollar payout. Asynchronous exits
separate the request from payout and recovery; the request transaction is
not payment.

Before offering a strategy, check [providers and eligibility](/docs/earn/providers).
See [Integration details](/docs/earn/integration-details) for fees, sponsorship,
swap-funded deposits, and retries, or the [API reference](/docs/reference/api/earn)
for exact schemas.
