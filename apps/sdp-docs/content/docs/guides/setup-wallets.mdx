---
title: Set Up Wallets
description: Initialize a custody provider and create wallets for signing transactions.
---

A **custody wallet** is a Solana keypair whose key is held and signed for by a custody provider — SDP routes signing requests to whichever provider holds the wallet's key. Initialize a provider, then create wallets for transfers and other onchain operations.

## Supported providers

| Provider | Description |
| --- | --- |
| **Privy** | Embedded wallet infrastructure platform |
| **Fireblocks** | Digital asset infrastructure company |
| **Coinbase CDP** | Embedded wallets for developers |
| **Para** | Wallet and authentication suite |
| **Turnkey** | Non-custodial wallet infrastructure platform |
| **DFNS** | Digital asset wallet infrastructure |
| **Anchorage** | Regulated institutional crypto custody |

<Tab value="Dashboard">

### 1. Open the wallet setup

Open the sidebar and click **Wallets**, then click **Create wallet**. If you haven't linked your organization yet, complete the [organization setup](/docs/guides/setup-organization) first.

### 2. Choose a custody provider

Under **Which provider holds the keys?**, select the provider that fits your setup and click **Continue**. The list shows only the providers your project can use; the provider cannot be changed after the wallet exists.

### 3. Choose a custody mode

When a provider is not set up yet and offers both modes, choose a **Custody mode**: **Managed** uses SDP's provider account, and **Bring your own credentials** connects your own provider app. Production projects offer only **Bring your own credentials** (see [Go to Mainnet](/docs/guides/go-to-mainnet)).

For your own credentials, fill in the provider's credential form (for Privy: a **Credential label**, the **Privy app ID** and **Privy app secret**, and an optional **Initial wallet label**) and click **Connect and verify**. This connects the account and returns you to the Wallets page.

### 4. Create the wallet

For Managed custody, or once the provider is set up, enter a **Wallet label**, pick a **Purpose**, and click **Create wallet**. When your project has an active connection with that provider, also choose the **Account** the wallet is created in: **Managed by SDP** (when the project has a Managed account) or one of your connections. Nothing is preselected: SDP has no default custody, so every wallet names where it lives.

The first wallet on a provider is always a transfer wallet; you can choose a purpose for wallets after it.

### 5. View your wallet

After provisioning, the wallet appears on the Wallets page with its address, wallet ID, and balance. To create additional wallets, click **Create wallet** again and repeat the process.

#### 1. Initialize the provider from the dashboard

Initializing a custody provider is provider setup (`wallets.configure`), and no API key can hold a `configure` action. An organization admin initializes it once per project, signed in to the dashboard (see the **Dashboard** tab); the dashboard calls `POST /v1/wallets/initialize` with that session. The same call made with an API key returns `403` with `details.action` set to `wallets.configure`.

Production projects use BYOK only. `POST /v1/wallets/initialize` sets up Managed custody, so in a Production project it returns `403` with `details.reason` set to `custody_mode_not_allowed`. Connect your own provider account to the project from the dashboard instead, then create wallets in that connection with `connectionId` using an API key that holds `wallets.manage`:

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/wallets \
  -H "Authorization: Bearer sf_..." \
  -H "Content-Type: application/json" \
  -d '{
    "connectionId": "cconn_123",
    "label": "Treasury wallet"
  }'
```

#### 2. Create additional wallets

Every wallet names the provider account it lives under: `provider` for the provider's Managed account, or `connectionId` for a connection your project added. Send exactly one of them. There is no default account to fall back to.

The `purpose` field is optional in the API. The dashboard sets it with the **Purpose** field.

Every operation that signs names its wallet; there is no default wallet. Transfers take the wallet's `id` (`cwlt_…`) as `sourceCustodyWalletId`. Other modules name it the same way (their pages say which field). An API key limited to selected wallets lists the same `id` in `walletIds`.

```typescript title="transfer-request.ts"
const body = {
  sourceCustodyWalletId: "cwlt_123", // `id` from GET /v1/wallets
  destination: "7xKXz...9fGh",
  token: "9aBCd...4eEf",
  amount: "100.00",
};
```
