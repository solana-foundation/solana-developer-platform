A **custody wallet** is a Solana keypair whose key is held and signed for by a custody provider — SDP routes signing requests to whichever provider holds the wallet's key. Initialize a provider, then create wallets for transfers and other onchain operations.

## Supported providers

| Provider | Description |
| --- | --- |
| **Privy** | Embedded wallet infrastructure platform |
| **Fireblocks** | Digital asset infrastructure company |
| **Coinbase CDP** | Embedded wallets for developers |
| **Para** | Wallet and authentication suite |
| **Turnkey** | Non-custodial wallet infrastructure platform |
| **DFNS** | Digital asset wallet infrastructure |
| **Anchorage** | Regulated institutional crypto custody |

### 1. Open wallet setup

Open **Wallets** in the sidebar and click **Create wallet**. Complete
[organization setup](/docs/guides/setup-organization) first if needed.

### 2. Choose a custody provider

Under **Which provider holds the keys?**, select a provider and click
**Continue**. The list shows the providers your project can use.

### 3. Set up the provider

If the provider offers both modes, choose **Managed** to use SDP's provider
account or **Bring your own credentials** to connect your own. Production
requires your own credentials; see [Go to mainnet](/docs/guides/go-to-mainnet).

For Privy, enter a **Credential label**, **Privy app ID**, **Privy app secret**,
and optional **Initial wallet label**. Click **Connect and verify** to connect
the account and create its first wallet.

![Privy provider setup with example credentials and a masked secret](/images/go-to-mainnet/04-connect-privy.png)

For Managed custody, enter a **Wallet label** and click **Create wallet**.
The first wallet is a transfer wallet.

### 4. Create additional wallets

Click **Create wallet** again, select the provider, and enter a **Wallet label**
and **Purpose**. If the provider has active connections, choose the **Account**
the wallet will belong to. Nothing is preselected. Click **Create wallet**.

### 5. View your wallet

After provisioning, the wallet appears on **Wallets** with its address and
balance. Open it to see its details.

#### 1. Initialize the provider from the dashboard

Initializing a custody provider is provider setup (`wallets.configure`), and no API key can hold a `configure` action. An organization admin initializes it once per project, signed in to the dashboard (see the **Dashboard** tab); the dashboard calls `POST /v1/wallets/managed-signing/initialize-with-wallet` with that session. The same call made with an API key returns `403` with `details.action` set to `wallets.configure`.

Production projects use BYOK only. `POST /v1/wallets/managed-signing/initialize-with-wallet` sets up Managed custody, so in a Production project it returns `403` with `details.reason` set to `custody_mode_not_allowed`. Connect your own provider account to the project from the dashboard instead, then create wallets in that connection with `connectionId` using an API key that holds `wallets.manage`:

```bash title="Terminal"
export IDEMPOTENCY_KEY=$(uuidgen)

curl -X POST https://api.solana.com/v1/wallets \
  -H "Authorization: Bearer sf_..." \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "connectionId": "cconn_123",
    "label": "Treasury wallet"
  }'
```

#### 2. Create additional wallets

Every wallet names the provider account it lives under: `provider` for the provider's Managed account, or `connectionId` for a connection your project added. Send exactly one of them. There is no default account to fall back to.

```java title="CreateWallet.java"
String idempotencyKey = java.util.UUID.randomUUID().toString();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.solana.com/v1/wallets"))
    .header("Authorization", "Bearer sf_...")
    .header("Idempotency-Key", idempotencyKey)
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString("""
        {
          "provider": "privy",
          "label": "Treasury wallet",
          "purpose": "transfer"
        }"""))
    .build();
```
</Tab>

The `purpose` field is optional metadata in the API. The dashboard exposes it
when creating additional wallets; the provider's first wallet is a transfer
wallet.
Reuse the same `Idempotency-Key` when retrying a wallet creation.

Every operation that signs names its wallet; there is no default wallet. Transfers take the wallet's `id` (`cwlt_…`) as `sourceCustodyWalletId`. Other modules name it the same way (their pages say which field). An API key limited to selected wallets lists the same `id` in `walletIds`.

```typescript title="transfer-request.ts"
const body = {
  sourceCustodyWalletId: "cwlt_123", // `id` from GET /v1/wallets
  destination: "7xKXz...9fGh",
  token: "9aBCd...4eEf",
  amount: "100.00",
};
```
