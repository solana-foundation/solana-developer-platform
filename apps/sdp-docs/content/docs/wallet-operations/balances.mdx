---
title: Wallet balances
description: Read the token balances of a custody wallet, with a USD value when a price source is configured.
---

`GET /v1/payments/wallets/{walletId}/balances` returns the balances that a custody wallet holds. It
returns the native **SOL** balance and every **SPL token** balance.

Each entry carries the raw amount, the amount in display units, the decimal count, and a USD value
when a price source is configured.

SOL is always the first entry. SDP returns it with `token: "SOL"` and
`mint: "So11111111111111111111111111111111111111112"`.

The `{walletId}` path segment takes the provider wallet ID, for example `privy_wallet_123`. It does
not accept the SDP wallet ID, and it does not accept the wallet address. See
[Which wallet identifier to use](/docs/wallet-operations#which-wallet-identifier-to-use).

## Response shape

SDP wraps the payload in the standard `data` and `meta` envelope. The balances sit under a
`walletBalances` key:

```json title="response.json"
{
  "data": {
    "walletBalances": {
      "walletId": "privy_wallet_123",
      "address": "3xYZa...2aBc",
      "balances": [
        {
          "token": "SOL",
          "mint": "So11111111111111111111111111111111111111112",
          "amount": "2500000000",
          "uiAmount": "2.5",
          "decimals": 9
        },
        {
          "token": "USDC",
          "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
          "amount": "1500000000",
          "uiAmount": "1500.00",
          "decimals": 6,
          "usdPrice": 1.0,
          "usdValue": 1500.0
        }
      ]
    }
  },
  "meta": { "requestId": "req_...", "timestamp": "2026-05-18T00:00:00.000Z" }
}
```

Each balance has these fields:

| Field | Notes |
| --- | --- |
| `token` | The token symbol when SDP knows it. Otherwise the onchain mint address. |
| `mint` | The onchain mint address. |
| `amount` | The amount in the smallest unit. It is a string, to keep full precision. |
| `uiAmount` | The amount in display units, as a decimal string. SDP divides `amount` by 10 to the power of `decimals`. |
| `decimals` | The decimal count of the token. |
| `usdPrice` | The USD price of one token. SDP omits it when it has no price data. |
| `usdValue` | The USD value of the whole balance. SDP multiplies `usdPrice` by `uiAmount`. SDP omits it when it has no price data. |
| `confidential` | Reserved for confidential transfer balances. It is absent for a standard balance. |

## Use cases

- **Account dashboards**. Show the contents of a custody wallet to the person who operates it.
- **Balance checks before a transfer**. Confirm that a wallet holds enough of one token before you
  start a payout batch.
- **Treasury accounting**. Take regular snapshots into your own ledger.

## Pricing freshness

When SDP returns a USD value, the price comes from the configured price source, and it is the most
recent quote that source has given.

The source and its update cadence depend on how your deployment is configured. Confirm both with
your operations team before you use `usdValue` for a balance-sheet decision. Until you have, treat
`amount` and `uiAmount` as the authoritative values, and convert them with your own price feed.

If no price source is configured, SDP omits `usdPrice` and `usdValue` instead of returning zero.
The missing field means "unknown", not "$0.00", so your code can decide how to handle the gap.

## Comparison to a Solana RPC call

You can also list SPL token balances yourself. Call `getTokenAccountsByOwner` on a Solana RPC
endpoint, then decode the token account data it returns.

Reasons to call the SDP `balances` endpoint instead:

- **Token resolution**. SDP resolves a mint address to a symbol when it knows one. A raw RPC call
  returns mint addresses only.
- **USD pricing**. An RPC endpoint has no price data.
- **No RPC dependency**. You call SDP already, so you keep one fewer external integration.

Reasons to call the RPC endpoint instead:

- **State at an exact slot**. An audit can require the wallet's balances at one specific slot.
- **Confidential transfer balances**. Full support for the extension is on the RPC side.
- **Latency**. The RPC endpoint is one hop closer to the Solana cluster.
