This section covers the controls that SDP applies to a custody wallet, and the record it keeps of
every decision.

A **wallet policy** applies to every operation on the wallet. The same policy covers payments,
ramps, issuance, signing, and calls to onchain programs. The part of SDP that starts the operation
does not change the result.

## What's in this section

- [Wallet policies](/docs/wallet-operations/policies). Set the default decision, restrict
  destinations, cap amounts, allow or deny operations, require an approval, and read the audit
  record.
- [Wallet balances](/docs/wallet-operations/balances). Read the token balances of a custody wallet,
  with a USD value when a price source is configured.

## Which wallet identifier to use

SDP gives every wallet two identifiers. Use the right one, or the request returns `404`.

| Identifier | Where it comes from | Where you use it |
| --- | --- | --- |
| Provider wallet ID, for example `privy_wallet_123` | The `walletId` field of `GET /v1/wallets` | The `{walletId}` path segment of every endpoint on this page, and the body of `POST /v1/wallets/default-wallet` |
| SDP wallet ID, for example `cwlt_abc123` | The `id` field of `GET /v1/wallets` | The `sourceCustodyWalletId` and `destinationCustodyWalletId` fields of the payments and ramps endpoints |

The endpoints on this page accept the provider wallet ID only. They do not accept the SDP wallet ID
and they do not accept the wallet address.

## Where these endpoints live

The wallet policy and balance endpoints sit under `/v1/payments/wallets`. They apply to the whole
wallet, not only to payments. A policy can cover the transfer, payment, ramp, issuance, and program
operation families.
