---
title: Rate limits
description: Each API key gets a set number of requests per minute, by its tier, and responses usually say how many are left.
---

Requests count against a limit per minute. A request with an API key counts against that key's tier; keys start on `standard`. A request without a key counts against its IP address.

<RateLimitTable />

These are the general limits. Some operations also have a tighter quota of their own, counted per key (or signed-in member) and per organization, so they can return `429` before the key reaches its tier's limit. While SDP's counter store is unavailable, those operations refuse with `503` rather than run uncounted.

Responses usually say where you stand. The headers are left off while SDP's shared counter store is unavailable, so don't depend on them:

| Header | Means |
| --- | --- |
| `X-RateLimit-Limit` | Requests allowed per window |
| `X-RateLimit-Remaining` | Requests left in this window |
| `X-RateLimit-Reset` | When this window ends, in Unix seconds |

Past the limit, a request gets `429` with the code `RATE_LIMITED` and a `Retry-After` header. Wait that many seconds before you send it again.
