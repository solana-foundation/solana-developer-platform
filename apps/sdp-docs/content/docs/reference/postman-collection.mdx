The collection is generated from the same public OpenAPI contract as the [API reference](/docs/reference/api), and holds every family published there. Internal families, such as `admin`, `onboarding`, `organizations`, `members`, and `api-keys`, are left out.

</ActionLinks>

After you import it, set two collection variables:

- `baseUrl`: the API host to call. It defaults to `https://api.solana.com`.
- `sdpApiKey`: your API key (`sf_...`), sent as a bearer token.

## Idempotency keys

Each route that requires an `Idempotency-Key` sends the one saved in its `idempotencyKey.<operationId>` collection variable. Postman creates the key when the variable is empty. It clears the key only after a final `2xx`, a replayed refusal, or a `422` other than `IDEMPOTENCY_KEY_REUSED`.

Every other answer keeps the key for the next send. That covers a transfer, batch, or schedule still `pending` or `processing` (poll it with `GET` until it's final), a timeout, a `5xx`, a `409` or `429`, a `400`, `401`, or `403` refusal, and `422 IDEMPOTENCY_KEY_REUSED`. See [Idempotency](/docs/developing-with-sdp/idempotency#the-dashboard-and-the-postman-collection).
