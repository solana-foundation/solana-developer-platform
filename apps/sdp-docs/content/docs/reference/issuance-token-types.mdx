SDP offers three **Tokenization Templates**:

| Template | Defaults | Notes |
| --- | --- | --- |
| `stablecoin` | 6 decimals; permanent delegate and pausable extensions; blocklist; new accounts initialized | Fiat-backed tokens with compliance controls. |
| `tokenized-security` | 8 decimals; permanent delegate and pausable extensions, optional scaled UI amount; allowlist; new accounts frozen | Regulated assets, with stronger defaults. |
| `custom` | 9 decimals; no extensions until you add them | For requirements the other two templates don't match. |

Every template allows up to 18 decimals. `GET /v1/issuance/templates` returns each template's current defaults.

Each token also has a **Token Access Control** mode, enforced onchain over who may hold or receive it. It's `allowlist` when `requiresAllowlist` is on; otherwise it's `blocklist` for `stablecoin` and `tokenized-security`, and `disabled` for `custom`. For `stablecoin` and `tokenized-security`, new accounts start frozen when the allowlist is on. This list belongs to the token, separate from an API key's [grants](/docs/developing-with-sdp/manage-api-keys#grants-by-module).

## Selecting a template

`stablecoin` and `tokenized-security` are vetted, fixed sets of Token-2022 extensions for one class of asset, not an à-la-carte menu. The nature of the instrument decides the template. Use `custom` for assets that fit neither model.

### Stablecoin

For tokens pegged to a fiat currency and redeemable at par (1:1). The template applies the controls regulated fiat tokens need: the **pausable** extension (stop transfers in an emergency) and a **permanent delegate** (seize or claw back tokens after a compliance event). A blocklist applies by default.

Stablecoins can't pay interest or yield to holders, and the template offers no interest-bearing extension. This follows payment-stablecoin frameworks such as the U.S. GENIUS Act and the EU's MiCA, which bar issuers from paying interest on the token itself. Interest- or yield-bearing products are issued as tokenized securities (typically funds) instead.

### Tokenized security

For regulated instruments: equity, debt or fund shares. The template applies the stablecoin controls with stronger defaults: the **allowlist** is on, so new accounts start **frozen** until approved, and the **scaled UI amount** extension is available for corporate actions such as splits or share-class rebasing. Interest- and yield-bearing instruments, such as debt or fund tokens, also use this template.

### Custom

Matches the **Non-security digital token** classification in the dashboard: assets that are neither fiat stablecoins nor regulated securities, such as commodities, real estate or collectibles. It offers the full Token-2022 extension set (transfer fees, transfer hooks, non-transferable, interest-bearing and others).

### Summary

| Instrument | Template |
| --- | --- |
| Pegged to a fiat currency, redeemable 1:1, with no yield | `stablecoin` |
| Regulated security (equity, debt, or fund), or an instrument that pays a return | `tokenized-security` |
| Any other asset, or one requiring extensions the other templates do not offer | `custom` (Non-security digital token) |

<Callout type="warn">
Token-2022 extensions are set when the mint is created and can't change afterward. The template choice is permanent for a token: changing it means issuing a new token.
</Callout>

This page is general guidance, not legal advice. Regulatory treatment depends on the jurisdiction and on how the instrument is structured.

## Amount format

Mint, burn, seize and force-burn request bodies take `amount` as a **decimal string in UI units**: the human-readable value, such as `"1"` or `"1.5"`. SDP converts it to base units with the token's `decimals`. Wallet balance responses differ: they return both the raw `amount` and `uiAmount`.
