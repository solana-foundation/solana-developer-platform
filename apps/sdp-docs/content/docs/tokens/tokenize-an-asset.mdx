Issue a stablecoin, a tokenized security, a loyalty token or any other asset through SDP. This page takes you from choosing a model to your first API call.

## Choose a token model

Pick the **Tokenization Template** that matches the asset's compliance and operating needs:

| Asset model | Template | Default controls |
| --- | --- | --- |
| Fiat-backed stablecoin | `stablecoin` | Freeze, pause, permanent delegate, blocklist |
| Tokenized security or RWA | `tokenized-security` | Freeze, pause, permanent delegate, allowlist |
| Loyalty, rewards or utility token | `custom` | Extensions you choose |
| Any other asset | `custom` | Extensions you choose |

At deploy, SDP gives every authority to the custody wallet that signs the deploy, unless you assign other custody wallets. While a custody wallet holds an authority, SDP signs the operations that authority controls, with no external signing. [Tokenization Templates](/docs/reference/issuance-token-types) lists each template's defaults.

## Compliance enforced onchain

Token-2022 extensions make compliance enforceable onchain. Freeze one holder's account, pause the token, seize or force-burn tokens, and manage the token's **Token Access Control** list. Freeze takes a `reason`; seize and force burn take a `memo`. Every token operation is one `POST` on the token:

## Audit trail

SDP records every issuance and compliance action in its audit log. Read one token's history with `GET /v1/issuance/tokens/{tokenId}/audit`, or on the token's **Activity** tab in the dashboard.

| Area | Recorded events |
| --- | --- |
| Token issuance | Create, edit, deploy, mint, burn, supply refresh and authority updates |
| Compliance | Freeze, unfreeze, pause, unpause, seize, force burn and access list changes |
| Asset profiles | Profile create, edit and delete |

## Idempotency

The calls that sign and send (deploy, mint, burn, force burn, freeze, unfreeze, pause, unpause, seize and authority updates) take an `Idempotency-Key` ([Idempotency](/docs/developing-with-sdp/idempotency)). A retry with the same key and body replays the first result instead of running again.

Issuance keys share one namespace across every operation and token in your organization. Reusing a key for a different request, even on another token, returns `409`. Create, edit and access list calls take no key.

## Core API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/v1/issuance/templates` | List token templates |
| `POST` | `/v1/issuance/tokens` | Create a token draft |
| `POST` | `/v1/issuance/tokens/{tokenId}/deploy` | Deploy to Solana |
| `POST` | `/v1/issuance/tokens/{tokenId}/mint` | Mint new supply |
| `POST` | `/v1/issuance/tokens/{tokenId}/burn` | Reduce supply |
| `POST` | `/v1/issuance/tokens/{tokenId}/allowlist` | Add an address to the access list |
| `POST` | `/v1/issuance/tokens/{tokenId}/freeze` | Freeze an account |
| `POST` | `/v1/issuance/tokens/{tokenId}/pause` | Pause all transfers |
| `POST` | `/v1/payments/transfers` | Transfer tokens |

See the full schemas in the [Issuance API reference](/docs/reference/api/issuance) and the [Payments API reference](/docs/reference/api/payments).

## Operational constraints

- Create a token before you deploy it, and deploy it before you mint or transfer it.
- While a token is paused, SDP refuses mint, burn, seize and force burn with `400 TOKEN_PAUSED`, and the pausable extension stops transfers onchain.
- Freeze and unfreeze take a holder's wallet address; SDP finds the token account.
- SDP signs only with authorities that a custody wallet in the project holds. An operation whose authority no custody wallet holds returns `409`. If an authority moves to a wallet outside SDP custody, its holder has to move it back.
