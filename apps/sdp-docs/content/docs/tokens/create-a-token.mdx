Creating a token saves its metadata, extensions and rules in SDP as a draft (`status: "pending"`). Nothing reaches Solana until you [deploy it](/docs/tokens/deploy-a-token).

![Empty Issuance page with a Create a draft button](/images/tokens/token-list-empty.png)

## Before you begin

- A custody wallet in the project ([Create a wallet](/docs/guides/setup-wallets)). The dashboard needs one to hold each key.
- For the API, a key with the `issuance.manage` grant.

## Templates

| Template | Decimals | Extensions | Use case |
| --- | --- | --- | --- |
| `stablecoin` | 6 | Permanent delegate, pausable | Fiat-backed tokens |
| `tokenized-security` | 8 | Permanent delegate, pausable, optional scaled UI amount; allowlist on by default | Regulated assets |
| `custom` | 9 | None until you add them | Full control |

The dashboard creates `stablecoin` tokens (**Stablecoin**) and `custom` tokens (**Non-security digital token**). Create a `tokenized-security` token through the API.

## How it works

<HowItWorks>

<Step number={1} title="Choose a template">

The template fixes the token's extensions and defaults. You review them before you create the draft.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

Open **Issuance** in the sidebar and click **Create a draft**. The flow has five steps.

On **What is this token?**, enter a **Name**, then choose a classification:

- **Stablecoin**: a token meant to hold a value, with freeze and pause switched on
- **Non-security digital token**: everything else, such as points, credits or tickets

Click **Continue**.

</Tab>
<Tab value="API">

List the templates to see what each one sets:

<ApiExample operation="list-token-templates" />

<ApiExample operation="list-token-templates" language="ts" />

Pass a template's `id` as `template` when you create the token. Without `template`, the token is `custom`.

<Step number={2} title="Set the token details">

Set the name, symbol and decimals. Symbol and decimals lock with the mint at deploy.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **Token details**, fill in:

- **Symbol**: up to 10 letters and digits, such as `ACME`
- **Decimals**: a stablecoin uses 6; other tokens start at 9
- **Description** and **Maximum supply** (optional; leave the cap empty for no cap)
- **Issuer name**: the legal entity issuing the token
- **Currency** (optional)

Click **Continue**.

<img src="/docs/images/tokens/token-create-identity.png" alt="Token details step with symbol ACME, 6 decimals, a description, issuer name and currency" width="693" height="679" style={{ display: "block", maxWidth: "100%", height: "auto", margin: "0 0 18px" }} />

</Tab>
<Tab value="API">

Send the details to `POST /v1/issuance/tokens`:

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens \
  -H "Authorization: Bearer sf_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Acme Dollar",
    "symbol": "ACME",
    "decimals": 6,
    "description": "USD-backed stablecoin",
    "template": "stablecoin"
  }'
```

`uri` is optional: an `http` or `https` URL of your metadata JSON. Without it, SDP serves the token's metadata JSON at `GET /v1/issuance/tokens/{tokenId}/metadata.json` and writes that URL onchain at deploy.

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={3} title="Choose controls and key holders">

Decide what the token can do and which wallet holds each of its keys.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **What this token can do**, choose the controls: **Freezable**, **Pausable**, **Permanent delegate**, **Access list** and **Mintable**. A stablecoin keeps all of them on, and its **Access list** is a blocklist or an allowlist. Any other token can turn them off, except **Mintable**, which is always on.

<img src="/docs/images/tokens/token-create-settings.png" alt="What this token can do step with every control on and Access list set to Allowlist" width="693" height="594" style={{ display: "block", maxWidth: "100%", height: "auto", margin: "0 0 18px" }} />

On **Who holds the keys**, choose a wallet for **Mint authority** (it also signs the deploy), **Metadata authority** and, when the token has them, **Freeze authority** and **Permanent delegate**.

<img src="/docs/images/tokens/token-create-keys.png" alt="Who holds the keys step with the Treasury wallet holding every authority" width="693" height="360" style={{ display: "block", maxWidth: "100%", height: "auto", margin: "0 0 18px" }} />

</Tab>
<Tab value="API">

Add the controls to the same body. `signingCustodyWalletId` is the SDP wallet `id` from `GET /v1/wallets` (`cwlt_…`), not the provider's `walletId` or the wallet's public key. It's optional on create; you can set it at deploy. `isMintable` and `isFreezable` default to `true`.

```typescript title="create-token.ts"
const res = await fetch("https://api.solana.com/v1/issuance/tokens", {
  method: "POST",
  headers: {
    Authorization: "Bearer sf_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "Acme Dollar",
    symbol: "ACME",
    decimals: 6,
    description: "USD-backed stablecoin",
    template: "stablecoin",
    signingCustodyWalletId: "cwlt_abc123",
    requiresAllowlist: false,
    isMintable: true,
    isFreezable: true,
  }),
});
```

For a custom token, set `template` to `"custom"` (or omit it) and pass `overrides.extensions`:

```typescript title="create-custom-token.ts"
body: JSON.stringify({
  name: "Game Coin",
  symbol: "GAME",
  decimals: 0,
  template: "custom",
  signingCustodyWalletId: "cwlt_abc123",
  overrides: {
    extensions: {
      pausable: {},
      transferFee: { basisPoints: 50, maxFee: "1000" },
    },
  },
  isMintable: true,
  isFreezable: false,
}),
```

The signing wallet gets every authority unless you assign other custody wallets with `authorityCustodyWalletIds` [at deploy](/docs/tokens/deploy-a-token).

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={4} title="Create the draft">

SDP stores the token with status `pending`. Nothing is written to Solana yet.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **Review**, check the draft and click **Create draft**. The **Draft created** toast confirms it, and the token's page opens in the **Draft** state.

**Save and exit** stores a complete draft in SDP. An unfinished one stays in this browser, under **Unfinished drafts** on Issuance.

![Issuance list with Acme Dollar marked Draft](/images/tokens/token-list-draft.png)

The draft's **Overview** tab holds **Deploy token**, the next step.

![Acme Dollar's Overview tab in the Draft state, with Deploy this token and its Deploy token button](/images/tokens/token-detail-pending.png)

</Tab>
<Tab value="API">

A `201` response returns the token:

```typescript title="create-token.ts"
const { data } = await res.json();
// data.token.id: keep it for every later call
// data.token.status: "pending"
// data.token.signingCustodyWalletId: the wallet selected for deployment
```

Pass `data.token.id` to [Deploy a Token](/docs/tokens/deploy-a-token).

</Tab>
</Tabs>
</StepPanel>

</Step>

</HowItWorks>
