---
title: Create a token
description: Define a new token from a template or your own configuration, and save it as a draft.
steps:
  - Choose a template
  - Configure token identity
  - Set operational settings
  - Confirm the draft
---

Creating a token defines its metadata, its extensions, and its operational rules. SDP saves the
result as a **draft**. A draft is not onchain yet. See [Deploy a token](/docs/tokens/deploy-a-token)
for the step that writes the mint account to Solana.

![Issuance page with no tokens yet and a card that starts a new token](/images/tokens/token-list-empty.png)

## Templates

| Template | Decimals | Key extensions | Use case |
| --- | --- | --- | --- |
| `stablecoin` | 6 | Permanent delegate, pausable | USD-backed tokens |
| `tokenized-security` | 8 | Permanent delegate, pausable, scaled UI amount, allowlist on by default | Regulated assets |
| `custom` | 9 | None — you choose | Full control |

These templates cover the common cases. `GET /v1/issuance/templates` returns every template that is
available to your project.

## How it works

<HowItWorks>

<Step number={1} title="Choose a template">

Select the **Template** that matches your asset model. A template pre-fills a set of extensions and
constraints. You can review them before you save the draft.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

The dashboard shows a card for each template:

- **Stablecoin**. USD-backed tokens with compliance controls.
- **Tokenized Security**. Regulated assets with the allowlist on by default.
- **Custom**. A Token-2022 setup that you configure yourself.

To open those cards and pick one:

1. Select **Issuance** in the sidebar.
2. Select **Add new token** on an empty Issuance page. Select **New** when the list already holds
   tokens.
3. Select a template.
4. Select **Continue**.

![Template cards for Stablecoin, Tokenized Security, and Custom, with one card selected](/images/tokens/token-create-templates.png)

</Tab>
<Tab value="API">

List the templates to see which fields each one pre-configures:

```bash title="Terminal"
curl https://api.solana.com/v1/issuance/templates \
  -H "Authorization: Bearer sk_test_..."
```

```typescript title="list-templates.ts"
const res = await fetch("https://api.solana.com/v1/issuance/templates", {
  headers: { Authorization: "Bearer sk_test_..." },
});
const { data } = await res.json();
// data[].id — use as the "template" value when creating
```

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={2} title="Configure token identity">

Set the core metadata of the token. This is the name, the symbol, the decimal count, and a URI that
points to your token metadata JSON.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Enter the **Metadata URI**. This is an HTTPS URL for the token metadata JSON.
2. Enter the **Token Name**, for example `Acme Dollar`.
3. Enter the **Symbol**. Use 1 to 10 characters, made of letters, numbers, or periods.
4. Enter the **Decimals**. The selected template sets the default value.
5. Select **Continue**.

![Identity form with the Metadata URI, Token Name, Symbol, and Decimals fields completed](/images/tokens/token-create-identity.png)

</Tab>
<Tab value="API">

Pass the identity fields in the `POST /v1/issuance/tokens` body:

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Acme Dollar",
    "symbol": "ACME",
    "decimals": 6,
    "description": "USD-backed stablecoin",
    "template": "stablecoin"
  }'
```

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={3} title="Set operational settings">

Choose the custody wallet that deploys the token. Configure Token Access Control and the supply
controls in the same place.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Select the **Main Signer**. This is the custody wallet that SDP uses for the deployment.
2. Set the transfer control. **Allowlist** lets only approved destinations receive the token.
   **Blocklist** blocks the listed destinations instead.
3. Select **Create draft** to save the token.

The `tokenized-security` template turns the allowlist on by default. You can change that setting
while the token is a draft.

![Operational settings with the Main Signer chosen and the Allowlist and Blocklist transfer controls visible](/images/tokens/token-create-settings.png)

</Tab>
<Tab value="API">

Add the operational fields to the same body.

`signingCustodyWalletId` is the exact SDP wallet `id` that `GET /v1/wallets` returns, for example
`cwlt_abc123`. Do not pass the provider-specific `walletId`. Do not pass the public key of the
wallet. You can omit the field while you draft the token and supply it when you deploy.

```typescript title="create-token.ts"
const res = await fetch("https://api.solana.com/v1/issuance/tokens", {
  method: "POST",
  headers: {
    Authorization: "Bearer sk_test_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "Acme Dollar",
    symbol: "ACME",
    decimals: 6,
    description: "USD-backed stablecoin",
    template: "stablecoin",
    signingCustodyWalletId: "cwlt_abc123",
    requiresAllowlist: false,
    isMintable: true,
    isFreezable: true,
  }),
});
```

For a custom token, omit `template` or set it to `"custom"`. Then pass `overrides.extensions`:

```typescript title="create-custom-token.ts"
body: JSON.stringify({
  name: "Game Coin",
  symbol: "GAME",
  decimals: 0,
  template: "custom",
  signingCustodyWalletId: "cwlt_abc123",
  overrides: {
    extensions: {
      pausable: {},
      transferFee: { basisPoints: 50, maxFee: "1000" },
    },
  },
  isMintable: true,
  isFreezable: false,
}),
```

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={4} title="Confirm the draft">

SDP saves the token with the status `pending`. SDP writes nothing to Solana at this point.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

A success message confirms that SDP saved the draft. The token then appears in the **Issuance**
list with a **Draft** badge.

![Issuance list with the new token and its Draft badge](/images/tokens/token-list-draft.png)

Open the token to see its detail page. The status reads **Not deployed**, and a **Deploy** control
takes you to the next step.

![Token detail page with the status Not deployed and the Deploy control available](/images/tokens/token-detail-pending.png)

</Tab>
<Tab value="API">

A successful response returns the new token object:

```typescript title="create-token.ts"
const { data } = await res.json();
// data.token.id     — save this; used in all subsequent calls
// data.token.status — "pending"
// data.token.signingCustodyWalletId — exact wallet selected for deployment
```

The token is not onchain yet. Pass `data.token.id` to
[Deploy a token](/docs/tokens/deploy-a-token).

</Tab>
</Tabs>
</StepPanel>

</Step>

</HowItWorks>
