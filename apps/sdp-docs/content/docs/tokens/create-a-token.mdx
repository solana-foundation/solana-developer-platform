Token creation defines your token's metadata, extensions, and operational rules. The token is saved in SDP but **not yet deployed** onchain — see [Deploy a Token](/docs/tokens/deploy-a-token) for the next step.

Creating a token requires the `tokens:write` permission.

## Templates

| Template | Default decimals | Key extensions | Use case |
| --- | --- | --- | --- |
| `stablecoin` | 6 | Permanent delegate, pausable | USD-backed tokens |
| `tokenized-security` | 8 | Permanent delegate, pausable; scaled UI amount available as an option; allowlist on by default | Regulated assets |
| `custom` | 9 | None — you choose | Full control |

The default decimals apply when you omit `decimals`. The `stablecoin` and `tokenized-security` templates also add the default account state extension: new accounts start frozen when the allowlist is on and initialized otherwise. See [Tokenization Templates](/docs/reference/issuance-token-types) for how to choose.

  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Acme Dollar",
    "symbol": "ACME",
    "decimals": 6,
    "description": "USD-backed stablecoin",
    "template": "stablecoin"
  }'

<Step number={3} title="Set operational settings">

Choose the exact SDP Wallet that will deploy the token, and configure Token Access Control and supply controls.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

In the **Controls** step:

- **Approved recipients** — turns on Token Access Control's allowlist mode, so only approved addresses can receive the token
- For a stablecoin, pause, freeze, and recovery controls are included
- For a Non-Security Digital Asset, choose **Emergency pause capability**, and under **Advanced controls**, interest-bearing balances or a transfer fee

In the **Permissions** step, choose an SDP wallet for each permission, such as **Who can mint tokens?** The wallet chosen for minting deploys the token.

</Tab>
<Tab value="API">

Add operational fields to the same body. `signingCustodyWalletId` is the exact SDP Wallet `id` returned by `GET /v1/wallets` (for example, `cwlt_*`), not the provider-specific `walletId` or the wallet's public key. You can omit it while drafting and provide it when you deploy.

```typescript title="create-token.ts"
const res = await fetch("https://api.solana.com/v1/issuance/tokens", {
  method: "POST",
  headers: {
    Authorization: "Bearer sk_test_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "Acme Dollar",
    symbol: "ACME",
    decimals: 6,
    description: "USD-backed stablecoin",
    template: "stablecoin",
    signingCustodyWalletId: "cwlt_abc123",
    requiresAllowlist: false,
    isMintable: true,
    isFreezable: true,
  }),
});
```

For a custom token, omit `template` or set it to `"custom"` and pass `overrides.extensions`:

```typescript title="create-custom-token.ts"
body: JSON.stringify({
  name: "Game Coin",
  symbol: "GAME",
  decimals: 0,
  template: "custom",
  signingCustodyWalletId: "cwlt_abc123",
  overrides: {
    extensions: {
      pausable: {},
      transferFee: { basisPoints: 50, maxFee: "1000" },
    },
  },
  isMintable: true,
  isFreezable: false,
}),
```

## Asset profile and hosted metadata

An **asset profile** is SDP's record of what a token represents. A token has at most one active profile, holding an `assetCategory` (`generic`, `stablecoin`, or `tokenized_security`), an `assetType` within that category, and `issuanceMetadata`.

`POST /v1/issuance/tokens` creates a default profile with the token: the category follows the template (`custom` maps to `generic`), the type is `generic`, and the metadata holds the token's name, description, and decimals. To set the profile yourself, create the token through `POST /v1/issuance/asset-profiles` instead. It takes the same body as `POST /v1/issuance/tokens` plus `assetCategory`, `assetType`, and `issuanceMetadata`, and creates the token and its profile together; if either write fails, neither is saved. The dashboard creates drafts this way.

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/asset-profiles \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Acme Dollar",
    "symbol": "ACME",
    "template": "stablecoin",
    "assetCategory": "stablecoin",
    "assetType": "fiat_backed",
    "issuanceMetadata": {
      "asset": { "name": "Acme Dollar", "issuerName": "Acme Financial Inc." },
      "chain": { "decimals": 6 }
    }
  }'
```

The response holds `data.token` and `data.assetProfile`. `GET /v1/issuance/asset-profiles/field-options` lists the valid categories and the types in each.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/v1/issuance/asset-profiles/by-token/{tokenId}` | Get a token's active profile |
| `GET` | `/v1/issuance/asset-profiles` | List profiles in the project |
| `PATCH` | `/v1/issuance/asset-profiles/{profileId}` | Update the category, type, or metadata |
| `DELETE` | `/v1/issuance/asset-profiles/{profileId}` | Archive a profile |

Reads need `tokens:read`; creating, updating, and archiving need `tokens:write`.

`issuanceMetadata` is private by default. Its `visibility.public` array lists the fields to publish; when you omit it, the asset type's default list applies. Only `asset.*` fields and `chain.decimals` can be published. `compliance` and `custom` fields are never published, even if you list them. The published subset is returned as `publicMetadata`.

If you create a token without a `uri`, deployment writes SDP's hosted metadata URL into the token's onchain metadata: `GET /v1/issuance/tokens/{tokenId}/metadata.json` on the SDP API. Anyone can fetch it without credentials. It returns `name` and `symbol`, plus `description` and `image` when set, merged with the profile's `publicMetadata`; the token's own fields win where they overlap. Tokens that are not yet deployed return `404`.

On a self-hosted deployment, set `PUBLIC_API_ORIGIN` to the API's public origin, or deploying a token without a `uri` fails. The profile fields in `metadata.json` also need `SDP_FLAG_ASSET_PROFILES` turned on. See the [Asset Profiles API reference](/docs/reference/api/asset-profiles) for the full schema.
