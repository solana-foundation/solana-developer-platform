After [deploying a token](/docs/tokens/deploy-a-token), you can mint new tokens to any address and burn tokens from accounts you control. Force-burn lets admins burn from any account without the holder's signature.

## Prerequisites

- A deployed token with status `active`
- `tokens:write` permission — or `tokens:admin` for force-burn
- For standard burn, the exact SDP Wallet `id` returned by `GET /v1/wallets` (for example, `cwlt_*`)

## How it works

<HowItWorks>

<Step number={1} title="Select the token and action">

Open the token you want to manage. Mint and burn are both available from the token detail page.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

In the **Issuance** list, open an active token.

The **Operations** section lists **Mint tokens** and **Burn tokens** under **Supply**. The token header shows the issued supply and the supply cap.

</Tab>
<Tab value="API">

All supply operations share this URL pattern:

```text title="Endpoints"
POST /v1/issuance/tokens/{tokenId}/mint
POST /v1/issuance/tokens/{tokenId}/burn
POST /v1/issuance/tokens/{tokenId}/force-burn
```

The `amount` field is a decimal string in **UI units** (human-readable token amounts). `"1"` means one token; `"1.5"` means one and a half. SDP converts to on-chain base units using the token's `decimals`.

`signingCustodyWalletId` always means the exact SDP Wallet `id`, not a provider-specific `walletId` or public key. It is required for a standard burn because that wallet owns and signs for the source. For mint and force-burn it is optional, but when supplied it must control the current mint or permanent-delegate authority. When omitted, SDP requires exactly one accessible wallet to match that live authority. Later actions never fall back to the token's deployment wallet.

SDP checks each mint, burn, and force-burn against the signing wallet's policy before signing. A `deny` returns `403 FORBIDDEN`; an operation held for approval returns `202` with error code `SIGNING_PENDING` and `error.details.approvalRequestId`. See [Wallet policies](/docs/wallet-operations/policies).

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={2} title="Mint tokens">

Issue new tokens to a destination address. SDP derives the associated token account automatically.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

Next to **Mint tokens**, click **Mint**. In the form:

- **Signing wallet** — the wallet that signs the mint; choose one when more than one is available
- **Destination** — wallet address to receive the new tokens
- **Amount** — in human-readable units (e.g., `1.0`)
- **Memo** — optional, recorded onchain

Click **Mint tokens**, then confirm the on-chain submission. A "Mint transaction finalized." toast appears once the mint confirms, and the **Activity** section lists the transaction.

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/mint \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: mint-001" \
  -d '{
    "signingCustodyWalletId": "cwlt_abc123",
    "mint": {
      "destination": "7xKXz...9fGh",
      "amount": "1000",
      "memo": "Initial distribution"
    }
  }'
```

```typescript title="mint-tokens.ts"
const res = await fetch(
  "https://api.solana.com/v1/issuance/tokens/tok_abc123/mint",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer sk_test_...",
      "Content-Type": "application/json",
      "Idempotency-Key": "mint-001",
    },
    body: JSON.stringify({
      signingCustodyWalletId: "cwlt_abc123",
      mint: {
        destination: "7xKXz...9fGh",
        amount: "1000",
        memo: "Initial distribution",
      },
    }),
  }
);
```

Control priority with `options.priorityFee`: `"none"`, `"low"`, `"medium"`, `"high"`, or a micro-lamport value.

To sign the mint yourself, call `POST /v1/issuance/tokens/{tokenId}/mint/prepare` with the same body. It returns an unsigned transaction in `preparedTransaction.serialized` for the authority wallet to sign and submit; that wallet pays the network fee, and SDP does not sponsor it. See the [execution model](/docs/developing-with-sdp#execution-model).

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={3} title="Burn tokens">

Reduce supply by burning from an account your wallet controls. Use force-burn to burn from any holder account without their signature.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

Next to **Burn tokens**, click **Burn**. Choose the signing wallet, then enter the **Source** that holds the tokens, the **Amount**, and an optional **Memo**.

Click **Burn tokens**, then confirm the on-chain submission. A "Burn transaction finalized." toast appears once the burn confirms.

For **Force burn** (requires `tokens:admin`), open **Recovery & permanent changes** in the **Operations** section. It appears for tokens with a permanent delegate and lets admins remove tokens from any holder account without their signature.

</Tab>
<Tab value="API">

**Burn from a controlled account:**

```typescript title="burn-tokens.ts"
await fetch("https://api.solana.com/v1/issuance/tokens/tok_abc123/burn", {
  method: "POST",
  headers: {
    Authorization: "Bearer sk_test_...",
    "Content-Type": "application/json",
    "Idempotency-Key": "burn-001",
  },
  body: JSON.stringify({
    signingCustodyWalletId: "cwlt_abc123",
    burn: { source: "3xYZa...2aBc", amount: "250", memo: "Redemption" },
  }),
});
```

**Force-burn from any holder** (requires `tokens:admin`):

```typescript title="force-burn-tokens.ts"
await fetch("https://api.solana.com/v1/issuance/tokens/tok_abc123/force-burn", {
  method: "POST",
  headers: {
    Authorization: "Bearer sk_test_...",
    "Content-Type": "application/json",
    "Idempotency-Key": "force-burn-001",
  },
  body: JSON.stringify({
    signingCustodyWalletId: "cwlt_abc123",
    forceBurn: { source: "3xYZa...2aBc", amount: "250", memo: "Compliance action" },
  }),
});
```

`POST /v1/issuance/tokens/{tokenId}/burn/prepare` and `POST /v1/issuance/tokens/{tokenId}/force-burn/prepare` take the same bodies and return an unsigned transaction in `preparedTransaction.serialized` for you to sign and submit. For a prepared burn, the signing wallet pays the network fee; SDP does not sponsor it. See the [execution model](/docs/developing-with-sdp#execution-model).

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={4} title="Refresh supply">

After minting or burning, refresh the cached supply total.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

The token header shows the **Issued supply**. Click the refresh icon next to it to read the current supply from the chain.

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/supply/refresh \
  -H "Authorization: Bearer sk_test_..."
```

Safe to include in automated post-mint workflows. It needs only `tokens:read`.

</Tab>
</Tabs>
</StepPanel>

</Step>

</HowItWorks>
