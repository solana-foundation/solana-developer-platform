Deploying [a draft](/docs/tokens/create-a-token) creates its mint on Solana with the draft's settings, signed by the custody wallet you choose. The mint lands on the project's network: devnet for a sandbox project, mainnet for production.

## Prerequisites

- A draft token (`status: "pending"`)
- The SDP wallet `id` that signs the deploy (`cwlt_…`, from `GET /v1/wallets`). It receives the mint authority.
- For the API, a key with the `issuance.execute` grant

## How it works

<Step number={2} title="Deploy the token">

SDP signs and sends the deploy with `signingCustodyWalletId`. A value in the request overrides the draft's wallet; without one, SDP uses the draft's. With neither, the request fails with `400`.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

Click **Deploy token**. In the **Deploy token** dialog, check the **Signing wallet** (choose one if several can sign), then click **Deploy token**.

<img src="/docs/images/tokens/token-deploy-modal.png" alt="Deploy token dialog with the Treasury signing wallet" width="449" height="320" style={{ display: "block", maxWidth: "100%", height: "auto", margin: "0 0 18px" }} />

SDP signs, sends and confirms the deploy in one request. The token shows **Deploying** while it runs, and you can leave the page.

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/deploy/execute \
  -H "Authorization: Bearer sf_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: deploy-acme-001" \
  -d '{"signingCustodyWalletId":"cwlt_abc123"}'
```

```typescript title="deploy-token.ts"
const res = await fetch(
  "https://api.solana.com/v1/issuance/tokens/tok_abc123/deploy/execute",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer sf_...",
      "Content-Type": "application/json",
      "Idempotency-Key": "deploy-acme-001",
    },
    body: JSON.stringify({ signingCustodyWalletId: "cwlt_abc123" }),
  }
);
const { data } = await res.json();
// data.token.mintAddress: the onchain mint address
```

Optional fields:

- `authorityCustodyWalletIds`: custody wallets for the `metadata`, `freeze` and `permanentDelegate` authorities. Roles the token has and you omit go to the signing wallet, unless the token's extensions already name an address. Naming a wallet for a role the token lacks returns `400`.
- `feePayment`: `sponsored` (the default) has SDP's fee sponsor pay. With `wallet`, the signing wallet pays rent and fees from its own SOL, and a wallet that can't cover them gets `400` before anything is sent.

Always send an `Idempotency-Key`. A retry with the same key never deploys twice: after a deploy that landed, it returns the deployed token. Reusing the key with a different body returns `409`.

If a deploy fails before the mint lands, the token returns to `pending`, so retry with a new key. If the mint lands but setting its metadata URI fails, SDP records the mint and returns `400 TRANSACTION_FAILED` with `details.mintAddress`. Don't redeploy.

<Step number={3} title="Confirm deployment">

Once the transaction confirms, the token is active and ready for minting and transfers.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

The toast reads "Deploy transaction finalized." and the token shows **Live onchain** with its mint address. Its operations open on the **Operations** tab, where **Transactions** lists the deploy.

If the deploy fails, the token shows **Deploy failed** with the reason, **Retry deploy** and **Open wallets**.

![Acme Dollar after the deploy: Live onchain, with Explorer and Mint tokens](/images/tokens/token-deployed.png)

</Tab>
<Tab value="API">

The deploy response carries the confirmed state:

```typescript title="deploy-token.ts"
// data.token.status: "active"
// data.token.mintAddress: for example "AcMeXYZ..."
// data.token.signingCustodyWalletId: the wallet that deployed
```

After deployment, `signingCustodyWalletId` only records who deployed. Mint and admin actions use each authority's current holder, and a standard burn uses its own source wallet; none fall back to the deployment wallet.

Fetch the token at any time to check:
