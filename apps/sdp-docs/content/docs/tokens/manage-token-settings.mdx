After you deploy a token, you can rotate its authorities and adjust its operational settings.

Authority management is not a compliance action. For freeze, pause, and seize, see
[Freeze and compliance](/docs/tokens/freeze-and-compliance).

## Choosing the signer for a metadata edit

`PATCH /v1/issuance/tokens/{tokenId}` accepts an optional `signingCustodyWalletId` for an onchain
metadata edit.

That field selects the exact custody record that controls the current metadata authority, for this
request only. It does not set a new deployment wallet, and it does not set a new authority.

If you omit the field, SDP requires exactly one matching in-scope record. Several matches return
`409`. A database-only edit needs no signer.

In the dashboard, SDP uses the one matching wallet automatically. When several wallets match,
choose one in the metadata confirmation, or beside the Save control for the asset profile. The
historical `data.token.signingCustodyWalletId` value does not change.

To find that signer after someone rotated the authority outside SDP, request
`GET /v1/issuance/tokens/{tokenId}?includeMetadataAuthority=true` and read `data.metadataAuthority`.

For a token that has a mint, SDP reads that value live from the chain. The stored snapshot in
`data.token.metadataAuthority` can therefore differ. A token without a mint returns its stored
metadata authority, or its mint authority, with no RPC call.

An RPC failure returns `502`. SDP never falls back to the stored value. The dashboard keeps
metadata errors and allowlist lookup errors separate, and the update rechecks the authority before
it signs. This read changes neither the stored token nor its deployment wallet.

## Prerequisites

- A deployed token with the status `active`
- The `tokens:admin` permission on the API key

Review the authorities and the configuration of the token before you change anything.

Fetch the current state of the token:

```bash title="Terminal"
curl https://api.solana.com/v1/issuance/tokens/tok_abc123 \
  -H "Authorization: Bearer sk_test_..."
```

```typescript title="get-token-settings.ts"
const { data } = await res.json();
// data.token.authorities — { mintAuthority, freezeAuthority, permanentDelegate }
// data.token.extensions  — active extensions on the token
// data.token.status      — "active" | "paused"
```

<Step number={2} title="Rotate an authority">

Move a token authority to a different wallet. Rotate an authority to move signing responsibility,
or to hand control to an external key holder.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Open the **Permissions** tab of the token detail page.
2. Select **Edit** next to the authority you want to change.
3. Select another controlled wallet, or select **Use custom address** and enter one.
4. Select **Save authority**.

![Authority dialog showing the current authority wallet, the list of controlled wallets, and the Save authority control](/images/tokens/token-authority-edit.png)

> After you rotate an authority to an external wallet, SDP can no longer sign the operations that
> need it. Rotate the authority back to a controlled wallet to use the SDP deploy, mint, and
> compliance actions again.

</Tab>
<Tab value="API">

SDP signs the authority rotation:

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/authority \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: rotate-001" \
  -d '{
    "authority": {
      "type": "mintAuthority",
      "newAuthority": "9aBCd...4eEf"
    }
  }'
```

`type` accepts `mintAuthority`, `freezeAuthority`, or `permanentDelegate`.

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={3} title="Clear an authority">

Clearing an authority removes it from the token permanently. You cannot undo it. The token then
stops being mintable, freezable, or delegatable, depending on which authority you clear.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Open the **Permissions** tab of the token detail page.
2. Select **Edit** next to the authority you want to clear.
3. Set the new authority to **None**.
4. Select **Save authority**.
5. Read the confirmation dialog. It explains what the change costs you, for example
   "Set Mint Authority to None?".
6. Select **Yes, set to None**.

</Tab>
<Tab value="API">

Set `newAuthority` to `null` to clear the authority:

```typescript title="revoke-authority.ts"
body: JSON.stringify({
  authority: {
    type: "mintAuthority",
    newAuthority: null,
  },
}),
```

After you clear the mint authority, nobody can ever mint this token again. The change is permanent
and you cannot undo it.

</Tab>
</Tabs>
</StepPanel>

</Step>
