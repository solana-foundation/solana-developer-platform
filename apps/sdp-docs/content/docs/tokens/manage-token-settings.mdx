After deployment, you can move a token's authorities to other wallets, give them up, and edit its metadata. Freeze, pause and seize are on [Freeze and Compliance](/docs/tokens/freeze-and-compliance).

## Prerequisites

- A deployed token
- The `issuance.authority` grant to move or revoke authorities, or `issuance.execute` to [edit metadata](#edit-metadata)

## How it works

<Step number={1} title="View current settings">

Review the token's authorities and configuration before you change them.

<StepPanel>

Open the token. **Overview** shows its supply, identity and authorities.

Below them, **Extensions** shows the template and whether the token is freezable, pausable and mintable, has a permanent delegate, and uses an access list.

![Extensions tab showing template, allowlist, mintable, freezable, and default account state settings](/images/tokens/token-settings-extensions.png)

</Tab>
<Tab value="API">

Fetch the token:

<ApiExample operation="get-token" />

`data.token` holds `mintAuthority`, `freezeAuthority`, `metadataAuthority`, `extensions` (including `permanentDelegate`) and `status` (`pending`, `active`, `paused` or `revoked`). For a live onchain lookup of one authority, add `includeMetadataAuthority`, `includeFreezeAuthority`, `includePauseAuthority` or `includeAllowlistAuthority=true`.

</Tab>
</Tabs>

<Step number={2} title="Rotate an authority">

Move an authority to another wallet, to change who signs or to hand control to an outside key holder.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **Permissions**, click **Edit** beside the authority. Pick another wallet, or click **Use custom address** and enter a Solana address. Then click **Save authority**.

![Mint Authority modal showing current authority wallet, new authority dropdown with controlled wallets, and Save authority button](/images/tokens/token-authority-edit.png)

> SDP can't sign with an authority held outside SDP custody, and can't take it back. Its holder must move it to a custody wallet before SDP can run the operations it controls.

</Tab>
<Tab value="API">

SDP signs the rotation:

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/authority \
  -H "Authorization: Bearer sf_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: rotate-001" \
  -d '{
    "authority": {
      "role": "mint",
      "newAuthority": "9aBCd...4eEf"
    }
  }'
```

`role` is `mint`, `freeze`, `permanentDelegate` or `metadata`. An optional `signingCustodyWalletId` must control the authority you're changing; `currentAuthority` is optional too.

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={3} title="Revoke an authority">

Remove an authority for good. Without its mint authority the token can never be minted again; without the freeze authority, accounts can't be frozen or unfrozen; without the permanent delegate, force transfer and force burn stop; without the metadata authority, metadata can't change.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **Permissions**, click **Edit**, choose **None** and click **Save authority**. The form explains what you give up; confirm with **Yes, set to None**.

On a token with an onchain access list, the dashboard lets you move the freeze authority but not remove it.

To end minting at the cap, use **Lock supply** on **Operations**: it mints what's left of the cap, then gives up the mint authority.

</Tab>
<Tab value="API">

Set `newAuthority` to `null`:

```typescript title="revoke-authority.ts"
body: JSON.stringify({
  authority: {
    role: "mint",
    newAuthority: null,
  },
}),
```

Revocation is permanent: once the mint authority is gone, no one can mint the token again.

</Tab>
</Tabs>
</StepPanel>

</Step>

</HowItWorks>

## Edit metadata

`PATCH /v1/issuance/tokens/{tokenId}` updates the stored token. On a deployed token, changes to `name`, `description`, `uri` and `imageUrl` are also written onchain through the current metadata authority. `symbol`, `decimals` and `requiresAllowlist` can't change after deployment.

`maxSupply` stays editable until the mint authority is revoked. It can't go below the minted supply, and `null` removes the cap.

For an onchain edit, the optional `signingCustodyWalletId` picks the custody wallet that holds the current metadata authority, for this request only. It doesn't change the deployment wallet. Without it, exactly one custody wallet in scope must match, or the call returns `409`. Edits that stay in SDP need no signer. After deployment, a request with only `signingCustodyWalletId` returns `400`.

In the dashboard, edit on the **Details** or **Public information** tab and click **Save changes**. When several wallets hold the metadata authority, choose one in the save bar.

If the authority moved outside SDP, look it up with `GET /v1/issuance/tokens/{tokenId}?includeMetadataAuthority=true`. For a minted token, `data.metadataAuthority` comes live from the chain; otherwise it's the stored metadata or mint authority, read without RPC. An RPC failure returns `502`, never the stored value. The lookup changes nothing.
