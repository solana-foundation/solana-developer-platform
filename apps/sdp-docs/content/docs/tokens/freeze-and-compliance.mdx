SDP gives you two kinds of compliance tooling for an issued token.

- **Token controls.** These are three separate operations. A freeze stops one holder from moving
  their balance. A pause stops every transfer of the token. A seize moves tokens away from a
  holder. Token controls need `isFreezable` on the token, or the `pausable` extension, depending
  on the operation.
- **Address screening.** Check a wallet against your configured compliance providers. Screen a
  wallet before you approve it as a destination, and before you add it to the Token Access Control
  allowlist of a token.

No compliance provider is enabled by default. Screening returns results only after an
administrator configures at least one provider for your organization.

Every token-control action needs the `tokens:admin` permission on the API key.

## How it works

<HowItWorks>

<Step number={1} title="Screen an address">

Check a Solana address against your configured compliance providers. Screen the address before you
onboard a wallet, and before you approve it as a transfer destination.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Open the Compliance section of the dashboard.
2. Select **Screen address**.
3. Enter the wallet address.
4. Select the intent, for example a transfer destination or a candidate for the Token Access
   Control allowlist.

The dashboard returns one result for each provider. Each result shows a risk level, a risk score,
and any flags.

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/compliance/address-screenings \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "address": "8dHEsGLp...hQWRGZ",
    "network": "solana",
    "intent": "transfer_destination"
  }'
```

```typescript title="screen-address.ts"
const { data } = await res.json();
// data.screening.providers[]
// → { provider, status, riskScore, riskLevel, message, evaluatedAt }
```

See the [Compliance API reference](/docs/reference/api/compliance) for the full schema.

<Step number={2} title="Freeze and unfreeze one balance">

A freeze stops one holder from sending or receiving this token. It targets one associated token
account. Other holders keep their normal access, and the token itself stays active.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Open the **Compliance** tab of the token detail page.
2. Select **Freeze or unfreeze a balance**.
3. Enter the wallet address of the holder.
4. Enter a reason. This field is optional.
5. Select **Freeze balance**.
6. Select **Freeze now** in the confirmation prompt to submit the transaction onchain.

![Freeze form with the wallet address and reason fields still empty](/images/tokens/freeze-controls-empty.png)

![Freeze form with the holder wallet address and a reason entered](/images/tokens/freeze-controls-filled.png)

![Confirmation prompt for the freeze transaction](/images/tokens/freeze-confirm.png)

The message "Freeze transaction finalized." appears, and the Frozen Accounts count changes to 1.

![Compliance tab with the finalized freeze message and a Frozen Accounts count of 1](/images/tokens/freeze-confirmed.png)

To lift a freeze:

1. Find the account in the frozen list.
2. Select **Unfreeze balance**.
3. Select **Unfreeze now** in the confirmation prompt to submit the transaction onchain.

![Confirmation prompt for the unfreeze transaction](/images/tokens/unfreeze-confirm.png)

The message "Unfreeze transaction finalized." appears, and the Frozen Accounts count returns to 0.

![Compliance tab with the finalized unfreeze message and a Frozen Accounts count of 0](/images/tokens/unfreeze-confirmed.png)

</Tab>
<Tab value="API">

Freeze one balance:

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/freeze \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "accountAddress": "3xYZa...2aBc",
    "reason": "Suspicious activity investigation"
  }'
```

`accountAddress` accepts the wallet address of a holder or its token account. SDP derives the
associated token account when it needs to.

Unfreeze that balance:

```typescript title="unfreeze-account.ts"
await fetch("https://api.solana.com/v1/issuance/tokens/tok_abc123/unfreeze", {
  method: "POST",
  headers: { Authorization: "Bearer sk_test_...", "Content-Type": "application/json" },
  body: JSON.stringify({ accountAddress: "3xYZa...2aBc" }),
});
```

List the frozen accounts:

```bash title="Terminal"
curl https://api.solana.com/v1/issuance/tokens/tok_abc123/frozen \
  -H "Authorization: Bearer sk_test_..."
```

<Step number={3} title="Pause and resume all transfers">

A pause stops every transfer and every mint of this token, for every holder. It is not a freeze. A
freeze affects one balance, and a pause affects the whole token. The token needs the `pausable`
extension.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Open the **Compliance** tab of the token detail page.
2. Select **Pause Controls**.
3. Select **Pause token**.
4. Select the signer, if several custody records control the same authority. The prompt uses the
   only matching authority wallet when there is one. The unpause control follows the same rules.
5. Confirm the onchain submission in the prompt.

![Pause Controls with the Pause token and Unpause token controls](/images/tokens/pause-controls.png)

![Confirmation prompt for the pause transaction](/images/tokens/pause-confirm.png)

The message "Pause transaction finalized." appears, and an orange **Token is paused** banner
appears across the page. SDP then blocks every supply operation and every transfer.

![Compliance tab with the Token is paused banner and the finalized pause message](/images/tokens/pause-confirmed.png)

To resume transfers, select **Unpause token** and confirm.

![Confirmation prompt for the unpause transaction](/images/tokens/unpause-confirm.png)

</Tab>
<Tab value="API">

```bash title="Terminal"
# Pause
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/pause \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{"signingCustodyWalletId":"cwlt_example"}'

# Unpause
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/unpause \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{"signingCustodyWalletId":"cwlt_example"}'
```

`signingCustodyWalletId` is optional when exactly one in-scope custody record matches the current
pause authority. Send `{}` to use that resolution.

Several matches without a selector return `409`. An explicit choice must control the live
authority, and it must pass the authorization checks and the runtime checks. Reusing an
idempotency key with a different wallet returns `409`.

While the token is paused, SDP rejects every transfer operation and every supply operation. They
work again after an unpause.

</Tab>
</Tabs>
</StepPanel>

</Step>

<Step number={4} title="Seize tokens from a holder">

A seize transfers tokens from a holder to a recovery address, without the signature of that
holder. It moves the tokens; it does not freeze them and it does not pause the token. Use it for
court orders and regulatory enforcement. The action needs `tokens:admin`.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

1. Open the **Compliance** tab of the token detail page.
2. Select **Force transfer**.
3. Enter the source address.
4. Enter the destination address.
5. Enter the amount.
6. Enter a memo. Record a memo for the audit trail.
7. Select **Transfer now** to submit the transaction onchain.

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/seize \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: seize-001" \
  -d '{
    "seize": {
      "source": "3xYZa...2aBc",
      "destination": "9aBCd...4eEf",
      "amount": "250",
      "memo": "Court order #12345"
    }
  }'
```

</Tab>
</Tabs>
</StepPanel>

</Step>

## Compliance response workflow

1. Screen the address through the Compliance API.
2. Freeze the balance of the affected holder while you investigate.
3. Act on the findings. Unfreeze the balance if the holder is cleared. Seize the tokens to a
   recovery address if you must move them. Force-burn the tokens if you must remove them from
   circulation. See [Mint and burn](/docs/tokens/mint-and-burn).
4. Record every action in a `memo` field for the audit trail.
