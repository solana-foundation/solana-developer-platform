SDP gives you two kinds of compliance tooling:

- **Token controls**: freeze one holder's account, pause every transfer, or seize tokens. Freeze needs a freezable token (`isFreezable`), pause needs the `pausable` extension, and seize needs the permanent delegate.
- **Address screening**: check a wallet against your compliance providers before you approve it as a destination or add it to the token's access list.

Token controls need the `issuance.enforce` grant on the API key; screening needs `compliance.execute`.

## How it works

<Step number={1} title="Screen an address">

Check a Solana address against your configured compliance providers before you onboard a wallet or approve it as a transfer destination.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">

</Tab>
<Tab value="API">

<ApiExample operation="screen-compliance-address" />

Set `intent` to `transfer_destination`, `wallet_address_addition` or `unknown` (the default). `network` defaults to `solana`.

`data.screening.providers[]` holds one result per provider (`range`, `elliptic`, `trm`, `chainalysis`): its `status` (`ok`, `pending`, `unavailable` or `error`), `riskScore` (which can be `null`), `riskLevel`, `message` and `evaluatedAt`.

See the [Compliance API reference](/docs/reference/api/compliance) for the full schema.

<Step number={2} title="Freeze and unfreeze an account">

</Tab>
<Tab value="API">

**Freeze:**

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/freeze-account \
  -H "Authorization: Bearer sf_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "accountAddress": "3xYZa...2aBc",
    "reason": "Suspicious activity investigation"
  }'
```

`accountAddress` takes a holder wallet or its token account; for a wallet, SDP finds the token account. A freeze returns `201` with `data.frozenAccount`. An optional `signingCustodyWalletId` must control the current freeze authority.

**Unfreeze:**

```typescript title="unfreeze-account.ts"
await fetch("https://api.solana.com/v1/issuance/tokens/tok_abc123/unfreeze-account", {
  method: "POST",
  headers: {
    Authorization: "Bearer sf_...",
    "Idempotency-Key": crypto.randomUUID(),
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ accountAddress: "3xYZa...2aBc" }),
});
```

<Step number={3} title="Pause and unpause the token">

Stop every transfer of the token at once. The token needs the `pausable` extension.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **Operations**, click **Pause** on the **Transfers** row.

![Transfers section on Operations with transfers Running and a Pause button](/images/tokens/pause-controls.png)

Read the warning, then click **Pause transfers**. It runs at once, unless several wallets hold the pause authority: then a dialog asks which one signs.

![Pause warning on the Transfers row with Pause transfers and Cancel](/images/tokens/pause-confirm.png)

The toast reads "Pause transaction finalized." and the token shows **Paused**: transfers are stopped, and holders keep their balances.

![Overview showing Paused: transfers are stopped and holders keep their balances, with Resume transfers](/images/tokens/pause-confirmed.png)

To resume, click **Resume** on the **Transfers** row and then **Resume transfers**. **Resume transfers** on **Overview** does the same after a confirmation.

<img src="/docs/images/tokens/unpause-confirm.png" alt="Resume transfers for all holders? confirmation with a warning, the signing wallet and Resume transfers" width="513" height="404" style={{ display: "block", maxWidth: "100%", height: "auto", margin: "0 0 18px" }} />

</Tab>
<Tab value="API">

**Pause:**

<ApiExample operation="pause-token" />

**Unpause:**

<ApiExample operation="unpause-token" />

`signingCustodyWalletId` is optional when exactly one custody wallet in scope holds the current pause authority; send `{}` to use it. Several matches without a selector return `409`. A wallet you name must control the live authority and pass the authorization and runtime checks. Reusing an idempotency key with a different wallet returns `409`.

While paused, SDP refuses mint, burn, seize and force burn with `400 TOKEN_PAUSED`, and the pausable extension stops transfers onchain. Pausing a paused token, or unpausing one that isn't, returns `400`.

<Step number={4} title="Seize tokens">

Move tokens from a holder to a recovery address without the holder's signature, using the permanent delegate. Use it for court orders and regulatory enforcement.

<StepPanel>
<Tabs items={["UI", "API"]} groupId="how-it-works">
<Tab value="UI">

On **Operations**, open **Recovery** and click **Force transfer**. Enter the **Source**, **Destination**, **Amount** and a **Memo** (recommended for the audit record), then click **Force transfer** and confirm with **Transfer now**.

</Tab>
<Tab value="API">

```bash title="Terminal"
curl -X POST https://api.solana.com/v1/issuance/tokens/tok_abc123/seize/execute \
  -H "Authorization: Bearer sf_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: seize-001" \
  -d '{
    "seize": {
      "source": "3xYZa...2aBc",
      "destination": "9aBCd...4eEf",
      "amount": "250",
      "memo": "Court order #12345"
    }
  }'
```

An optional `signingCustodyWalletId` must control the current permanent delegate. The destination must pass the token's access list: on an allowlist token it must be listed (`403 NOT_ON_TOKEN_ALLOWLIST`), and on a blocklist token it must not be (`403 ON_TOKEN_BLOCKLIST`).

</Tab>
</Tabs>
</StepPanel>

</Step>

## Compliance response workflow

1. **Screen** the address with the Compliance API.
2. **Freeze** the account while you investigate.
3. Based on the findings, **unfreeze** it if cleared, **seize** its tokens to a recovery address, or **force-burn** them (see [Mint and Burn](/docs/tokens/mint-and-burn)).
4. Record a reason or memo on every action for the audit trail.
