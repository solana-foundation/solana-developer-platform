import { Step, Steps } from "fumadocs-ui/components/steps";

This tutorial takes a fresh self-hosted install from healthy containers to the first useful devnet
workflow. You log into the dashboard, initialize a local wallet, create a wallet-scoped API key, and
make an authenticated API call.

Use this page after the [Quickstart](/docs/self-hosting/quickstart). The path here runs on devnet
only, and it uses the default local signer. Set up a provider-specific signer in a later hardening
pass.

<Callout type="warn">
The public Solana devnet RPC endpoint is useful for a smoke test. It can also be rate-limited or
incomplete for balance-heavy wallet pages. The public endpoint `https://api.devnet.solana.com`
rejects `getTokenAccountsByOwner`, so wallet balances do not load against it. Use a dedicated devnet
endpoint from an RPC provider before you treat this flow as reliable.
</Callout>

<Steps>

<Step>

## Confirm the stack is healthy

Run these commands from the directory where the installer placed `compose.yml` and `.env`:

```bash title="Terminal"
cd ~/sdp
docker compose up -d
docker compose ps
curl http://localhost:8787/health
```

The health call returns a JSON response with `status: "ok"`. The dashboard is at
`http://localhost:3000` and the API is at `http://localhost:8787`. The self-hosted documentation
site is at `http://localhost:3001`.

</Step>

<Step>

## Configure Clerk for dashboard login

Work in your Clerk development app:

- Copy the publishable key, the secret key, and the issuer into the
  [configurator](/docs/self-hosting/configurator).
- Customize the session token in the Clerk dashboard, under **Sessions** and then **Customize
  session token**. Use the claims from the
  [Clerk setup guide](https://github.com/solana-foundation/solana-developer-platform/blob/main/apps/sdp-api/docs/self-hosting/clerk-setup.md).
- Expose your local API with the webhook tunnel. Reserve a free stable domain at
  [dashboard.ngrok.com/domains](https://dashboard.ngrok.com/domains), set it as
  `WEBHOOK_INGEST_DOMAIN` in `apps/sdp-api/.env.local`, and run `pnpm dev:webhooks`.
- Create a webhook endpoint that points at `https://<your-domain>/webhooks/clerk/link-orgs`. Clerk
  delivers over the public internet, so it cannot reach `localhost` directly.
- Copy the webhook signing secret into `CLERK_WEBHOOK_SECRET`.

Raw environment validation treats `CLERK_WEBHOOK_SECRET` as optional. This tutorial requires it,
because the webhook is what creates the local SDP organization record after dashboard signup.

</Step>

<Step>

## Generate the devnet `.env`

Open the [configurator](/docs/self-hosting/configurator) and keep the defaults for the first
deployment. Fill in the following:

- `SOLANA_RPC_URL` with a devnet RPC endpoint.
- The Clerk publishable key, secret key, issuer, and webhook secret.
- Local signing with native fee payment.

The signing step generates a local Solana signer in the browser. It then shows the public key that
you fund on devnet. Save the generated file as `~/sdp/.env`, then restart the stack:

```bash title="Terminal"
cd ~/sdp
docker compose up -d
```

<Callout type="info">
In self-hosted mode, SDP entitles every provider that is configured in the environment. A provider
that is not configured stays unavailable. The default devnet path therefore offers only the local
signer.
</Callout>

</Step>

<Step>

## Log into the dashboard

Open `http://localhost:3000` and sign in through Clerk. Create or join an organization when the
dashboard prompts you. After the Clerk webhook lands, the dashboard shows the organization and
project context instead of onboarding errors.

If the dashboard loads but the organization state does not appear, check the API logs:

```bash title="Terminal"
docker compose logs -f sdp-api
```

Look for Clerk webhook errors, session token claim mismatches, or a missing
`CLERK_WEBHOOK_SECRET`.

</Step>

<Step>

## Initialize a local custody wallet

In the dashboard, open **Wallets**. Choose the local provider. Create a wallet named
`Devnet local wallet`.

You can also use the API path. Use an admin key from the dashboard:

```bash title="Terminal"
curl -X POST http://localhost:8787/v1/wallets/initialize \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "local",
    "walletLabel": "Devnet local wallet"
  }'
```

Copy the returned `walletId`. You bind the API key to this wallet in the next step.

</Step>

<Step>

## Create a wallet-scoped API key

Open **API keys** in the dashboard and create a **Sandbox** key. A Sandbox key targets the devnet
cluster, which is what this tutorial uses.

Choose **Selected wallets**. Select the local wallet you created in the previous step. Set it as
the key's default wallet.

Save the full key while the dashboard shows it. SDP displays it only once.

</Step>

<Step>

## Verify the key can read wallets

Use the new key against your self-hosted API:

```bash title="Terminal"
export SDP_API_KEY="sk_test_..."

curl "http://localhost:8787/v1/wallets?view=summary" \
  -H "Authorization: Bearer $SDP_API_KEY"
```

The response includes the local wallet you created. You now have a self-hosted devnet stack with
dashboard authentication, local custody signing, and an API key bound to the one wallet it is
allowed to use.

</Step>

</Steps>
