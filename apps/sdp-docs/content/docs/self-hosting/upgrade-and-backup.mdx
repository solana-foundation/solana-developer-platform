title: Upgrade and backup
description: Move a self-hosted Solana Developer Platform to a new release and protect its data.

This page covers two operations. It shows how to upgrade to a new release, and how to back up the
data that matters on a self-hosted stack.

## Upgrade to a new release

A release ships new container images and an updated `compose.yml`. Follow these steps:

1. **Refresh the install files.** Run the install script again. It replaces `compose.yml` with the
   new release's version, verified against the release checksums. It leaves any existing `.env` and
   `.env.example` in place. It prints a link to the new release's `.env.example`, so that you can
   check for new variables.

   ```bash title="Terminal"
   curl -fsSL https://github.com/solana-foundation/solana-developer-platform/releases/latest/download/install.sh | bash
   ```

2. **Pin the version.** Set `SDP_VERSION` in `.env` to the release tag you are upgrading to, rather
   than `latest`. Every service then runs the same, known build.

3. **Pull and restart.**

   ```bash title="Terminal"
   cd ~/sdp
   docker compose pull
   docker compose up -d
   ```

   `sdp-migrate` runs any new database migrations once, before the API starts.

4. **Verify** that the services are healthy, as in the
   [Quickstart](/docs/self-hosting/quickstart#4-verify).

To upgrade to a specific release instead of the latest one, set `INSTALL_VERSION` when you run the
script. Set the matching `SDP_VERSION` in `.env`.

### Roll back a release

Set `SDP_VERSION` back to the previous tag, then run `docker compose up -d`.

Note that SDP does not reverse a migration automatically. If a release applied a migration, restore
from a backup taken before the upgrade. Do not rely on a version downgrade alone.

## Back up your data

Two things hold your state:

- **The Postgres database** holds all platform data. With the bundled database, that data lives in
  the `sdp-postgres-data` Docker volume. With an external `DATABASE_URL`, back the data up with
  your database provider's tooling instead.
- **Your `.env` file** holds the secrets and the configuration. Store it somewhere safe, such as a
  secret manager. You cannot regenerate it identically.

Redis is a cache. You do not need to back it up.

### Back up the database

Take a logical dump with `pg_dump` from the running container. Running it through `sh -c` lets
`pg_dump` read `POSTGRES_USER` and `POSTGRES_DB` from inside the container, so custom values are
honored:

```bash title="Terminal"
cd ~/sdp
docker compose exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > sdp-backup.sql
```

Keep these dumps off-host. Take them on a schedule that matches your recovery needs.

### Restore the database

A plain `pg_dump` includes the full schema and the migration history. Restore it into an **empty**
database, and let the stack start on top of it.

Do not restore over a database that is already migrated. The dump's schema then collides with the
schema that `sdp-migrate` created on the previous `up`.

```bash title="Terminal"
cd ~/sdp
docker compose down                       # stop every service
docker volume rm sdp_sdp-postgres-data    # discard the current database (destructive)
docker compose up -d postgres             # start a fresh, empty Postgres
until docker compose exec -T postgres \
  sh -c 'pg_isready -U "$POSTGRES_USER"' >/dev/null 2>&1; do sleep 1; done
docker compose exec -T postgres \
  sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < sdp-backup.sql
docker compose up -d                      # start the rest
```

On that final `up`, `sdp-migrate` skips every migration already recorded in the restored dump. A
dump taken at the same release leaves it with nothing to do. An older dump, restored before an
upgrade, lets it apply only the newer migrations.

Restore the matching `.env` file alongside the data, so that secrets such as
`CUSTODY_ENCRYPTION_KEY` line up with the data they protect. For an external `DATABASE_URL`,
restore through your database provider rather than through the bundled `postgres` service.
