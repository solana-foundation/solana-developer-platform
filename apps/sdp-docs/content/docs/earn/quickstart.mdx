A deposit is three calls: prepare it, submit the signed transaction, then poll
until it settles. Your app signs with the customer's wallet in between, and SDP
never holds keys. To see the whole flow offline,
[run the example](https://github.com/solana-foundation/solana-developer-platform/tree/main/examples/earn-quickstart).

You need a [devnet API key](https://platform-devnet.solana.com/dashboard?return_to=%2Fdashboard%2Fapi-keys%2Fnew)
with **Earn Execute**. Every `POST` takes an `Idempotency-Key`: resend the same
key and body after a lost response, and SDP returns the original response
instead of a second deposit.

## 1. Prepare

Send `POST /v1/earn/deposit` with a strategy from
[discovery](/docs/earn/strategies), the wallet that signs and owns the position,
and the amount in token units:

```json title="deposit.json"
{
  "strategyId": "<strategy-id>",
  "source": { "ownerAddress": "<wallet-address>" },
  "amount": { "mint": "<deposit-mint>", "value": "10" },
  "slippageBps": 50
}
```

<Tabs items={["TypeScript", "curl"]}>
<Tab value="TypeScript">
```ts
const api = "https://api-devnet.solana.com";
const headers = { Authorization: `Bearer ${apiKey}`, "Content-Type": "application/json" };

const prepared = await fetch(`${api}/v1/earn/deposit`, {
  method: "POST",
  headers: { ...headers, "Idempotency-Key": prepareKey },
  body: JSON.stringify(deposit),
});
const { operation } = (await prepared.json()).data;
```
</Tab>
<Tab value="curl">
```bash
curl -sS https://api-devnet.solana.com/v1/earn/deposit \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $PREPARE_KEY" \
  --data-binary @deposit.json
```
</Tab>
</Tabs>

SDP returns `202` with an operation. It builds and simulates the transaction,
but never signs or sends it:

```json title="202 response (trimmed)"
{
  "data": {
    "operation": {
      "id": "op_…",
      "status": "prepared",
      "actionId": "opa_…",
      "version": 1,
      "terms": {
        "estimate": { "mint": "<share-mint>", "value": "9.84" },
        "minimum": { "mint": "<share-mint>", "value": "9.79" },
        "fees": null
      },
      "nextAction": {
        "type": "sign_transaction",
        "transaction": "<base64-unsigned-transaction>",
        "lastValidBlockHeight": "312345678",
        "expiresAt": null
      }
    }
  }
}
```

Show your customer `terms`: `estimate` is the quoted share amount, `minimum` is
the least the transaction accepts, and `null` means unknown, not zero.

## 2. Sign and submit

Have the owner's wallet [sign](https://solana.com/docs/core/transactions)
`nextAction.transaction` without changing it, before the network passes
`lastValidBlockHeight` (about a minute). Then send
`POST /v1/operations/{operationId}/submit` with the reviewed action and the
signed transaction, base64-encoded:

```json title="submission.json"
{
  "actionId": "opa_…",
  "version": 1,
  "signedTransaction": "<base64-signed-transaction>"
}
```

<Tabs items={["TypeScript", "curl"]}>
<Tab value="TypeScript">
```ts
await fetch(`${api}/v1/operations/${operation.id}/submit`, {
  method: "POST",
  headers: { ...headers, "Idempotency-Key": submitKey },
  body: JSON.stringify({
    actionId: operation.actionId,
    version: operation.version,
    signedTransaction,
  }),
});
```
</Tab>
<Tab value="curl">
```bash
curl -sS "https://api-devnet.solana.com/v1/operations/$OPERATION_ID/submit" \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $SUBMIT_KEY" \
  --data-binary @submission.json
```
</Tab>
</Tabs>

`202` means SDP matched the signed bytes to the transaction it prepared. It
broadcasts them and tracks the outcome.

## 3. Poll

<Tabs items={["TypeScript", "curl"]}>
<Tab value="TypeScript">
```ts
let current = operation;
while (!["completed", "failed", "cancelled"].includes(current.status)) {
  await new Promise((resolve) => setTimeout(resolve, 3000));
  const response = await fetch(`${api}/v1/operations/${operation.id}`, { headers });
  current = (await response.json()).data.operation;
}
```
</Tab>
<Tab value="curl">
```bash
curl -sS "https://api-devnet.solana.com/v1/operations/$OPERATION_ID" \
  -H "Authorization: Bearer $SDP_API_KEY"
```
</Tab>
</Tabs>

`completed` means SDP verified delivery, and `result.positionId` is the new
position. `failed` means it didn't go through: read `error`, then prepare a new
deposit with a new key. Any other status is still in progress, so keep polling
and don't start another deposit.

<Callout>
**Using an [SDP custody wallet](/docs/wallet-operations)?** Send
`source: { "walletId": "<wallet-id>" }` instead of `ownerAddress`, and submit
without `signedTransaction`: SDP requests the signature from the wallet's
custody provider.
</Callout>
