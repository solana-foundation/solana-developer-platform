The replacement Earn contract is internal pending named security sign-off.
Use an authenticated credential scoped to your project and environment.
Reads require `earn.read`; deposit and withdrawal actions require `earn.execute`.

## Discover a strategy

Call `GET /v1/earn/discovery`. Select a returned strategy ID and check its
capabilities, supported mint and withdrawal terms. A catalogue listing does not
guarantee that your wallet can deposit.

## Prepare a deposit

Persist an `Idempotency-Key` and send `POST /v1/earn/deposit`:

```json
{
  "strategyId": "strategy_example",
  "source": { "walletId": "cwlt_example" },
  "amount": { "mint": "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU", "value": "100" },
  "slippageBps": 50
}
```

Use `ownerAddress` instead of `walletId` when the owner signs through your app.
Review the returned operation's terms. Preparation returns `202` and does not
sign or broadcast.

## Execute and track

Call `POST /v1/operations/{operationId}/execute` with the returned `actionId`
and `version`. Include `signedTransaction` when the advertised next action asks
the owner to sign. Persist a separate idempotency key for execution.

Poll `GET /v1/operations/{operationId}`. Show provider approval instructions when
requested and continue tracking while the next action is `wait`. Read holdings
with `GET /v1/earn/positions`.

To exit, prepare `POST /v1/earn/withdraw` with the returned `positionId` and
`{ "amount": { "kind": "all" } }`, then follow the same operation flow.
