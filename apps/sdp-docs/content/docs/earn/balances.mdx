`GET /v1/earn/positions` lists a wallet's holdings, with `api` and `headers` as
in the [quickstart](/docs/earn/quickstart):

<Tabs items={["TypeScript", "curl"]}>
<Tab value="TypeScript">
```ts
const response = await fetch(`${api}/v1/earn/positions?ownerAddress=${ownerAddress}`, {
  headers,
});
const { positions } = (await response.json()).data;
```
</Tab>
<Tab value="curl">
```bash
curl -sS "https://api-devnet.solana.com/v1/earn/positions?ownerAddress=<wallet-address>" \
  -H "Authorization: Bearer $SDP_API_KEY"
```
</Tab>
</Tabs>

Each position's `id` is the `positionId` you [withdraw](/docs/earn/withdrawals)
with; the [position object](/docs/earn/api-overview#position) lists its fields. Without `ownerAddress`, the list covers every position your key can see
in the project. See [position filters](/docs/reference/api/earn/list-earn-core-positions).

Tracked holdings verified empty during a read are omitted from the list. Keep
tracking outstanding withdrawals through their operations. Pages fill any gaps:
when `hasMore` is true, the page contains `limit` holdings and a `nextCursor`.

## Read one position

`GET /v1/earn/positions/{positionId}` returns one position, with the same fields
as the list:

<Tabs items={["TypeScript", "curl"]}>
<Tab value="TypeScript">
```ts
const response = await fetch(`${api}/v1/earn/positions/${encodeURIComponent(positionId)}`, {
  headers,
});
const position = (await response.json()).data;
```
</Tab>
<Tab value="curl">
```bash
curl -sS "https://api-devnet.solana.com/v1/earn/positions/<position-id>" \
  -H "Authorization: Bearer $SDP_API_KEY"
```
</Tab>
</Tabs>

- Any `id` from the list works, including holdings found with `discover=true`.
  The ID already names the owner and strategy, so no wallet filter is needed.
- Reading a discovered holding doesn't start tracking it. If SDP already tracks
  it, the response carries the tracked `id`.
- An unknown position, or one outside your project, returns `404`. A
  discovered holding SDP can't verify right now returns `503`.
- A balance read right after a transaction can lag. When the operation is
  `completed` and its `resourceRef.kind` is `earn.movement`, pass its
  `resourceRef.id` as `afterMovementIds` to read a balance that includes it.
  Another position's movement returns `404`.

  The response's `balanceReadContext.minimumSlot` is the floor for refreshing
  the funding wallet at the same point. Refresh that wallet and position
  together; keep the previous values if either read fails.

  `balanceReadContext.minimumSlotMovementId` identifies the accepted movement
  proving that position's strongest floor. Keep it for the next refresh instead
  of accumulating every completed movement ID.
  This also returns an authorized closed position after a full exit, so you can
  remove its empty holding and refresh the wallet together.

A value SDP couldn't read live is left out, never shown as zero. See
[position parameters](/docs/reference/api/earn/get-earn-position).

## Holdings opened outside SDP

Add `discover=true` to an `ownerAddress` list to include the wallet's holdings
in integrated strategies that SDP didn't open. You can withdraw from them the
same way. `discovery.unavailableStrategyCount` counts strategies SDP couldn't
read: their balances are unknown, not zero. Holdings found this way have no
purchase history, so their `costBasisKnown` is `false`.

A withdrawal starts tracking a discovered holding, and it stays listed while it
holds a balance, even if that withdrawal fails. Withdrawing through a discovered
ID of a holding SDP already tracks uses that holding and keeps its cost basis.

## Totals and earnings

`includeSummary=true` totals everything the filter selects, not only the
current page. Add `includeOwnerAddresses=true` for totals per owner; with that
set, `includePositions=true` adds each position.

Show earned yield only where `costBasisKnown` is `true`;
`summary.costBasisCoverage` is `complete` when that holds for every position.
Keep pending queue shares and intermediate tokens visible until they settle.

## Activity

`GET /v1/operations?ownerAddress=<wallet-address>` lists the wallet's deposits
and withdrawals, newest first, each with its current `nextAction`. Always pass
`ownerAddress` here: unlike the positions list, an unfiltered operations list
leaves out every `ownerAddress` operation. Narrow it with:

- `status=active` for everything not yet final, including preparations still
  waiting for a signature or a route choice.
- `kind=earn.deposit` or `kind=earn.withdraw` for one type.
- `operationIds=op_a,op_b` for up to 100 known operations in one read. Use
  `limit=100` for the full set, or follow `nextCursor`.
- `limit` and `cursor` to page through history.

Full history can push an older pending operation past the first page.
`status=active` applies before paging, so it returns every unfinished operation
up front. See [activity filters](/docs/reference/api/earn/list-operations).
