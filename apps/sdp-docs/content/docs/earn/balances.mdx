`GET /v1/earn/positions` reads a wallet's holdings, with `api` and `headers` as
in the [quickstart](/docs/earn/quickstart):

<Tabs items={["TypeScript", "curl"]}>
<Tab value="TypeScript">
```ts
const response = await fetch(`${api}/v1/earn/positions?ownerAddress=${ownerAddress}`, {
  headers,
});
const { positions } = (await response.json()).data;
```
</Tab>
<Tab value="curl">
```bash
curl -sS "https://api-devnet.solana.com/v1/earn/positions?ownerAddress=<wallet-address>" \
  -H "Authorization: Bearer $SDP_API_KEY"
```
</Tab>
</Tabs>

Each position's `id` is the `positionId` you [withdraw](/docs/earn/withdrawals)
with. Without `ownerAddress`, the read covers every position your key can see in
the project. See [position filters](/docs/reference/api/earn/list-earn-core-positions).

## Holdings opened outside SDP

Add `discover=true` to an `ownerAddress` read to include the wallet's holdings
in integrated strategies that SDP didn't open. You can withdraw from them the
same way. `discovery.unavailableStrategyCount` counts strategies SDP couldn't
read: their balances are unknown, not zero. Discovered holdings have no
acquisition history, so their `costBasisKnown` is `false`.

## Totals and earnings

`includeSummary=true` totals the whole selected scope, not only the current
page. Add `includeOwnerAddresses=true` for totals per owner, and
`includePositions=true`, which needs it, for each position.

Show earned yield only where `costBasisKnown` is `true`; `summary.costBasisCoverage`
is `complete` when that holds for every position. Keep pending queue shares and
intermediate tokens visible until they settle.

## Activity

`GET /v1/operations?ownerAddress=<wallet-address>` lists the wallet's deposits
and withdrawals, newest first, each with its current `nextAction`. Always pass
the owner: without a filter, the list leaves out owner-address operations.
