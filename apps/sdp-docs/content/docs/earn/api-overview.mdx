Earn has ten endpoints. Three read strategies and positions, two prepare a
deposit or withdrawal, and five submit and track the operation that comes
back. Every call takes your API key as `Authorization: Bearer <key>`, and every
`POST` an `Idempotency-Key`. Each endpoint links to its full reference, with
every parameter, field and error.

## Endpoints

| Endpoint | Send | Returns |
| --- | --- | --- |
| [`GET /v1/earn/discovery`](/docs/reference/api/earn/discover-earn-strategies) | Optional filters, such as `depositMint` | A page of [strategies](#strategy) |
| [`GET /v1/earn/positions`](/docs/reference/api/earn/list-earn-core-positions) | `ownerAddress`; optional `discover`, `includeSummary` | A page of [positions](#position) |
| [`GET /v1/earn/positions/{positionId}`](/docs/reference/api/earn/get-earn-position) | A position `id` | One [position](#position) |
| [`POST /v1/earn/deposit`](/docs/reference/api/earn/prepare-earn-deposit) | `strategyId`, `source.ownerAddress`, `amount` | An [operation](#operation) to sign |
| [`POST /v1/earn/withdraw`](/docs/reference/api/earn/prepare-earn-withdrawal) | `positionId`, `amount` | An [operation](#operation) to sign, or a route to choose |
| [`GET /v1/operations`](/docs/reference/api/earn/list-operations) | `ownerAddress`; optional `status`, `kind`, `operationIds` | A page of [operations](#operation) |
| [`GET /v1/operations/{operationId}`](/docs/reference/api/earn/get-operation) | Nothing | One [operation](#operation) |
| [`POST /v1/operations/{operationId}/submit`](/docs/reference/api/earn/submit-operation) | `actionId`, `version`, `signedTransaction` | The [operation](#operation), now `queued` |
| [`POST /v1/operations/{operationId}/refresh`](/docs/reference/api/earn/refresh-operation) | `actionId`, `version`, `optionId` | The [operation](#operation), with the chosen route to sign |
| [`POST /v1/operations/{operationId}/cancel`](/docs/reference/api/earn/cancel-operation) | An empty body, `{}` | The [operation](#operation), now `cancelled` |

Every response wraps its payload in `data`, beside a `meta` object with the
`requestId`. Errors return `{ "error": { "code", "message", "details" } }` with
a matching HTTP status; the Earn-specific `409` reasons are in
[integration details](/docs/earn/integration-details#refresh-and-cancel).

## How the calls fit together

1. Find a strategy with `GET /v1/earn/discovery`.
2. Prepare with `POST /v1/earn/deposit` or `POST /v1/earn/withdraw`. You get an
   operation back.
3. If its `nextAction.type` is `select_option`, choose a route with
   `/refresh`.
4. Sign `nextAction.transaction` with the owner's wallet, then `/submit` it.
5. Poll the operation until it is final, then read the position for the new
   balance.

The [quickstart](/docs/earn/quickstart) runs steps 2, 4 and 5 for a deposit.

## Strategy

One yield product that you can deposit into. Discovery returns a page of these:

```json title="Strategy (trimmed)"
{
  "id": "earn_strategy_3b6a81ce-00b0-4c5a-9761-cb359932e97e",
  "provider": "kamino",
  "name": "Allez USDC",
  "depositMints": ["4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU"],
  "shareMint": "hXm2xSRF5PLKGMrTvAWqKhR76MuJX5dAabeSChkjqu2",
  "liquidityTerm": "instant",
  "fundable": true,
  "rate": { "value": "0.062", "observedAt": "2026-11-20T14:00:00.000Z" },
  "capabilities": { "deposit": true, "withdraw": true }
}
```

| Field | What it tells you |
| --- | --- |
| `id` | Pass it as `strategyId` when you deposit. |
| `depositMints` | The tokens it takes directly. Another token adds a swap. |
| `shareMint` | The receipt token a deposit gives you. |
| `rate.value` | The provider-reported APY as a decimal fraction: `"0.062"` is 6.2%. `null` is unknown. |
| `liquidityTerm` | `instant`, or `delayed` when withdrawals queue. |
| `capabilities.deposit`, `fundable` | When both are `true`, it takes deposits. |

More on choosing one in [Strategies](/docs/earn/strategies).

## Position

One wallet's holding in one strategy. The positions endpoints return these:

```json title="Position (trimmed)"
{
  "id": "earn_position_3b6a81ce-00b0-4c5a-9761-cb359932e97e",
  "strategyId": "earn_strategy_3b6a81ce-00b0-4c5a-9761-cb359932e97e",
  "source": { "ownerAddress": "9WzDXwBbmkg8ZTbNMqUxvQRAyrZzDsGYdLVL9zYtAWWM" },
  "label": "Allez USDC",
  "tokenMint": "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU",
  "shareMint": "hXm2xSRF5PLKGMrTvAWqKhR76MuJX5dAabeSChkjqu2",
  "shares": "25.42",
  "withdrawableShares": "25.42",
  "tokenValue": "25.81",
  "costBasisKnown": true
}
```

| Field | What it tells you |
| --- | --- |
| `id` | Pass it as `positionId` when you withdraw. |
| `shares` | Strategy shares held. `withdrawableShares` is what you can withdraw now. |
| `tokenValue` | The live value in the deposit token, `tokenMint`. |
| `costBasisKnown` | `false` when SDP doesn't know what was paid, so earnings are unknown. |

A live value SDP couldn't read is left out, never shown as zero. More in
[Balances and earnings](/docs/earn/balances).

## Operation

One deposit or withdrawal, from preparation to payout. Preparing returns one,
and every call after that returns its new state:

```json title="Operation (trimmed)"
{
  "id": "op_5f2a9c1e-8d4b-4f6a-9b3e-2c7d1a0e6f84",
  "kind": "earn.deposit",
  "status": "prepared",
  "actionId": "opa_0c8e1f4a-6b2d-4e9a-8f3c-5d7b9a1e2c40",
  "version": 1,
  "nextAction": {
    "type": "sign_transaction",
    "transaction": "<base64-unsigned-transaction>",
    "lastValidBlockHeight": "312345678",
    "expiresAt": null
  },
  "terms": {
    "inputAmount": { "mint": "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU", "value": "100" },
    "estimate": { "mint": "hXm2xSRF5PLKGMrTvAWqKhR76MuJX5dAabeSChkjqu2", "value": "98.41" },
    "minimum": { "mint": "hXm2xSRF5PLKGMrTvAWqKhR76MuJX5dAabeSChkjqu2", "value": "97.92" },
    "fees": null,
    "options": []
  },
  "canCancel": false,
  "resourceRef": null,
  "result": null,
  "error": null
}
```

| Field | What it tells you |
| --- | --- |
| `id` | Every `/v1/operations/{operationId}` call takes it. |
| `status` | Where it is, in the table below. |
| `nextAction` | What to do next: sign, choose a route, or wait. See [next actions](/docs/earn/integration-details#next-actions). |
| `actionId`, `version` | The exact transaction you were shown. Send both back with `/submit` or `/refresh`. |
| `terms` | What the customer agrees to: `inputAmount`, the quoted `estimate`, the enforced `minimum`, known `fees`, and route `options` for a withdrawal. |
| `canCancel` | Whether `/cancel` works right now. |
| `resourceRef` | After submit, the record SDP tracks. An `earn.movement` `id` works as `afterMovementIds` on position reads. |
| `result` | Once final: `positionId`, `signature`, `settledAmount` and `settlementOutcome`. |
| `error` | When it failed: a `code` and a `message`. |

| `status` | Meaning |
| --- | --- |
| `prepared` | Built and waiting for a signature or a route choice. |
| `queued` | Submitted; SDP is about to broadcast it. |
| `awaiting_signature` | Waiting on a signature step. Keep polling. |
| `submitted` | Broadcast and waiting to confirm; for a queued withdrawal, its request. |
| `settling` | Confirmed and waiting for the provider to pay out. |
| `completed` | Done, and SDP verified delivery. |
| `failed` | It didn't go through; `error` says why. |
| `cancelled` | Stopped before anything moved. |

Every field is in the reference, for example
[Get an operation](/docs/reference/api/earn/get-operation).
