A deposit from a customer's wallet is a build, a signature, and a submit. The
[Embedded Yield quickstart](/docs/earn/quickstart) runs one end to end; this
page covers what each step takes, returns, and expects you to save. For a
custody wallet, see the [Treasury guide](/docs/earn/treasury#deposit).

| Step | Request | Grant |
| --- | --- | --- |
| Preview, when the strategy needs a floor | [`POST /v1/earn/vault-deposit-previews`](/docs/reference/api/earn/create-earn-vault-deposit-preview) | `earn.read` |
| Build | [`POST /v1/earn/external-wallet/deposit-transactions`](/docs/reference/api/earn/create-earn-external-wallet-deposit-transaction) | `earn.execute` |
| Sign | In the customer's wallet | |
| Submit | [`POST /v1/earn/external-wallet/deposits`](/docs/reference/api/earn/create-earn-external-wallet-deposit), with an `Idempotency-Key` | `earn.execute` |
| Track | [`GET /v1/earn/external-wallet/movements/{movementId}`](/docs/reference/api/earn/get-earn-external-wallet-movement) | `earn.read` |

## Preview the deposit

A preview quotes the shares a deposit would receive right now. It moves
nothing and reserves nothing.

```bash title="Terminal"
curl -sS https://api.solana.com/v1/earn/vault-deposit-previews \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "strategyId": "earn_strategy_3b6a81ce-00b0-4c5a-9761-cb359932e97e",
    "amount": "25"
  }'
```

```json title="Response (trimmed)"
{
  "data": {
    "strategyId": "earn_strategy_3b6a81ce-00b0-4c5a-9761-cb359932e97e",
    "sharesOut": "25",
    "shareDecimals": 6,
    "blockingIssues": []
  }
}
```

Resolve every `blockingIssues` entry before you build, even on a `200`. When
the strategy's `depositSlippage` is not null, compute `minSharesOut` from
`sharesOut`; see [Slippage floors](/docs/earn/integration-details#slippage-floors).
Ignore `feeSponsored`: it describes Treasury custody wallets, never a
customer's wallet.

## Build the transaction

| Field | Use |
| --- | --- |
| `strategyId` | The strategy to deposit into. |
| `ownerAddress` | The customer's wallet. It signs, and it holds the position. |
| `amount` | A decimal string in the deposit token, `depositMints[0]`. |
| `minSharesOut` | The slippage floor. Required when `depositSlippage` is not null, refused when it is null. |
| `feePayer` | Optional. A wallet of yours that pays the fee and rent; see [Fees and sponsorship](/docs/earn/integration-details#fees-and-sponsorship). |
| `sourceTokenMint` | Optional. Another stablecoin to fund from; see [Swap-funded deposits](/docs/earn/integration-details#swap-funded-deposits). |

```bash title="Terminal"
curl -sS https://api.solana.com/v1/earn/external-wallet/deposit-transactions \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "strategyId": "earn_strategy_3b6a81ce-00b0-4c5a-9761-cb359932e97e",
    "ownerAddress": "Af89Mkuvo6AcLDbs7Fxs1FPsnnbD9KrY9NfmaFXHqmPo",
    "amount": "25"
  }'
```

```json title="Response (trimmed)"
{
  "data": {
    "transaction": {
      "transactionId": "earn_external_wallet_transaction_b116f3ed-5f19-41b1-85cd-8afe6b37875d",
      "transaction": "AQAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA...",
      "lastValidBlockHeight": "14846",
      "sponsored": false,
      "ownerAddress": "Af89Mkuvo6AcLDbs7Fxs1FPsnnbD9KrY9NfmaFXHqmPo",
      "provider": "kamino",
      "tokenMint": "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU",
      "amount": "25",

}
```

Keep `transactionId` with the base64 `transaction`. The network accepts it
until block height `lastValidBlockHeight`, about a minute after the build, so
sign and submit promptly.

## Sign in your customer's wallet

The wallet signs the exact bytes, without changing or broadcasting them. With
a [Wallet Standard](https://github.com/wallet-standard/wallet-standard) wallet
and `@solana/react` (`npm install @solana/react@8 @solana/kit@8`), sign the
transaction and check that the wallet returned it unchanged:

```typescript title="use-sign-in-wallet.ts"
import { useWalletAccountTransactionSigner } from "@solana/react";
import {
  getBase64EncodedWireTransaction,
  getBase64Encoder,
  getTransactionDecoder,
} from "@solana/kit";

type WalletAccount = Parameters<typeof useWalletAccountTransactionSigner>[0];

/** Signs SDP's base64 transaction in the customer's connected wallet. */
export function useSignInWallet(account: WalletAccount) {
  // Use "solana:mainnet" for a production project.
  const signer = useWalletAccountTransactionSigner(account, "solana:devnet");
  return async (transactionBase64: string): Promise<string> => {
    const unsigned = getTransactionDecoder().decode(getBase64Encoder().encode(transactionBase64));
    // Wallet Standard signers may modify before signing, so check the result below.
    const [signed] = await signer.modifyAndSignTransactions([unsigned]);
    if (!signed) throw new Error("The wallet returned no signed transaction");
    const unchanged =
      signed.messageBytes.length === unsigned.messageBytes.length &&
      signed.messageBytes.every((byte, index) => byte === unsigned.messageBytes[index]);
    if (!unchanged) throw new Error("The wallet changed the transaction; build a new one");
    return getBase64EncodedWireTransaction(signed);
  };
}
```

Send the signed transaction to your backend, which submits it. SDP refuses a
changed transaction with `400`, so ask for a fresh build when the check
fails. Never broadcast from the wallet: SDP broadcasts after it records the
deposit. A custody or MPC signer follows the same rule; see
[What the wallet must support](/docs/earn/concepts#what-the-wallet-must-support).

## Submit it

Send the build's `transactionId` and the signed transaction, with a new
`Idempotency-Key`.

```bash title="Terminal"
curl -sS https://api.solana.com/v1/earn/external-wallet/deposits \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c9f0e-6d1c-4b5c-9a53-0f4f7b6f2a11" \
  -d '{
    "transactionId": "earn_external_wallet_transaction_b116f3ed-5f19-41b1-85cd-8afe6b37875d",
    "signedTransaction": "AVhP3mB1c2lnbmVkIHRyYW5zYWN0aW9u..."
  }'
```

```json title="Response (trimmed)"
{
  "data": {
    "deposit": {
      "movementId": "earn_movement_505a6c34-f804-4abd-b6a9-315d031bdf1f",
      "positionId": "earn_position_2f8b6b04-7147-487e-b760-b1caa4fbcb8b",
      "direction": "deposit",
      "status": "submitted",
      "settlement": "atomic",
      "signature": "3dhkSPLiQZQPXL96fWzMdWJtdbtAffkBKXw2xhsYbV3VNSnYrVAcdx1czsnLsE1ou4SvLecGdSYe4QpAuZdfjJAf",
      "amount": "25",
      "tokenMint": "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU",
      "tokenAmount": null,
      "replayed": false
    }
  }
}
```

- **Save before you send.** Store the idempotency key with the signed
  transaction. If the response is lost, send both again unchanged: SDP returns
  the original deposit with `replayed: true`. See
  [Retry safely](/docs/earn/integration-details#retry-safely).
- **Save the position.** Keep `positionId` with the strategy's
  `withdrawalSlippage`, storing `null` explicitly. A strategy can leave the
  catalog while its positions stay withdrawable, and the exit uses this saved
  policy.
- **Read the amount at `finalized`.** On some strategies `tokenAmount` is null
  until then.

## Track it to finality

Poll the movement until its status is `finalized` or `failed`, on the
[polling schedule](/docs/earn/integration-details#poll-politely).
[How a movement settles](/docs/earn/concepts#how-a-movement-settles) says when
you may show it as done.

## Errors

[Errors](/docs/earn/integration-details#errors) lists every code a deposit can
return, and [Retry safely](/docs/earn/integration-details#retry-safely) says
what to do after each one. Two matter most on a submit:

| Status | When | What to do |
| --- | --- | --- |
| `400 BAD_REQUEST` | No `Idempotency-Key`, or the signed transaction differs from the build, or a signature is missing or invalid. | Send a key. Otherwise build again and sign the exact bytes. |
| `409 CONFLICT` | The key was used for a different build, or the same build arrives under a new key. | Retry with the original build and key. Use a new key only for a new deposit. |
