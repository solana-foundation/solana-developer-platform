title: Withdraw funds
description: Choose a live withdrawal route, withdraw instantly or by request, and confirm the payout reached the customer's wallet.
---

A withdrawal spends shares from a position and pays the deposit token back to
the wallet that owns it. Some routes pay in the same transaction; others pay
later. Read the live routes first.

## 1. Choose a route

[`POST /v1/earn/external-wallet/withdrawal-options`](/docs/reference/api/earn/get-earn-external-wallet-withdrawal-options)
reads each route from live provider state.

```bash title="Terminal"
curl -sS https://api.solana.com/v1/earn/external-wallet/withdrawal-options \
  -H "Authorization: Bearer $SDP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"positionId": "earn_position_0432ffeb-c574-4b11-80dc-a09defb68fcc"}'
```

```json title="Response (trimmed)"
{
  "data": {
    "positionId": "earn_position_0432ffeb-c574-4b11-80dc-a09defb68fcc",
    "instant": true,
    "providerOrder": false,
    "queued": true,
    "queueAsset": {
      "assetMint": "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU",
      "allowWithdrawals": true,
      "secondsToMaturity": 3600,
      "minimumSecondsToDeadline": 60,
      "maximumSecondsToDeadline": 7776000,
      "minimumDiscountBps": 0,
      "maximumDiscountBps": 100,
      "minimumShares": "0.000001",
      "shareDecimals": 6
    },
    "parRedemption": null
  }
}
```

| Route | When it is offered | Pays out |
| --- | --- | --- |
| Instant withdrawal | `instant: true` | In the same transaction. |
| Provider order | `providerOrder: true` | Later, when the provider completes the order. |
| Solver queue | `queued: true`, with live terms in `queueAsset` | Later, at a discount, when a solver fulfills the request. |
| Operator redemption | `parRedemption` is present | Later, at par, when the operator settles the request. |

A position offers an instant withdrawal or a provider order, never both, and
the same endpoints build whichever it offers. When several routes are offered,
let your customer choose. Never infer a route from the strategy's
`liquidityTerm`. A failed read or missing terms means the route is
unavailable, not that it pays zero.

## 2. Withdraw instantly

An instant withdrawal works like a deposit. Withdraw at most the position's
live `withdrawableShares`: a preview does not check the wallet's balance.

| Step | Request |
| --- | --- |
| Preview | [`POST /v1/earn/external-wallet/withdrawal-previews`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-preview) |
| Build | [`POST /v1/earn/external-wallet/withdrawal-transactions`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-transaction) |
| Submit | [`POST /v1/earn/external-wallet/withdrawals`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal), with an `Idempotency-Key` |
| Track | [`GET /v1/earn/external-wallet/movements/{movementId}`](/docs/reference/api/earn/get-earn-external-wallet-movement) |

`withdraw` takes the position you saved after the deposit, a share amount,
and a `sign` function for the customer's wallet. It imports `floor.ts` from
[Slippage floors](/docs/earn/integration-details#slippage-floors):

```typescript title="withdraw.ts"
import { randomUUID } from "node:crypto";
import { floorForTolerance } from "./floor";

const api = "https://api.solana.com/v1/earn/external-wallet";
const headers = {
  Authorization: `Bearer ${process.env.SDP_API_KEY}`,
  "Content-Type": "application/json",
};

/** Returns the response's `data`, or throws the API's error. */
async function data(response: Response) {
  const body = await response.json();
  if (!response.ok) throw new Error(`${body.error.code}: ${body.error.message}`);
  return body.data;
}

const post = (path: string, body: object, extraHeaders = {}) =>
  fetch(`${api}${path}`, {
    method: "POST",
    headers: { ...headers, ...extraHeaders },
    body: JSON.stringify(body),
  }).then(data);

type SavedPosition = {
  positionId: string;
  ownerAddress: string;
  withdrawalSlippage: { defaultToleranceBps: number } | null;
};
type PositionPage = {
  positions: { id: string; withdrawableShares?: string }[];
  nextCursor: string | null;
};

/** Withdraws `shares` from a saved position. `sign` is the customer's wallet. */
export async function withdraw(
  saved: SavedPosition,
  shares: string,
  sign: (transaction: string) => Promise<string>,
) {
  // Read the position's live balance, following `nextCursor` through every page.
  let position: PositionPage["positions"][number] | undefined;
  let before: string | null = null;
  do {
    const query = new URLSearchParams({ ownerAddress: saved.ownerAddress, limit: "100" });
    if (before) query.set("before", before);
    const page: PositionPage = await fetch(`${api}/positions?${query}`, { headers }).then(data);
    position = page.positions.find((p) => p.id === saved.positionId);
    before = page.nextCursor;
  } while (!position && before);
  if (position?.withdrawableShares === undefined) {
    throw new Error("The saved position cannot withdraw right now");
  }

  const preview = await post("/withdrawal-previews", { positionId: saved.positionId, shares });
  if (preview.blockingIssues.length > 0) {
    throw new Error(`Preview blocked: ${JSON.stringify(preview.blockingIssues)}`);
  }

  // Send a floor only when the saved policy takes one. An exit never needs the catalog.
  const policy = saved.withdrawalSlippage;
  const minAmountOut = policy
    ? floorForTolerance(preview.assetsOut, preview.assetDecimals, policy.defaultToleranceBps)
    : undefined;

  const { transaction: built } = await post("/withdrawal-transactions", {
    positionId: saved.positionId,
    shares,
    minAmountOut,
  });
  const signedTransaction = await sign(built.transaction);

  // In production, save the key with the signed transaction before you send.
  const { withdrawal } = await post(
    "/withdrawals",
    { transactionId: built.transactionId, signedTransaction },
    { "Idempotency-Key": randomUUID() },
  );
  return withdrawal; // Track `withdrawal.movementId` as you track a deposit.
}
```

```json title="Preview response"
{
  "data": {
    "positionId": "earn_position_e3053c7b-e41e-4f21-b4dc-e229ab95f40b",
    "assetsOut": "10",
    "assetDecimals": 6,
    "blockingIssues": []
  }
}
```

- **The preview quotes the payout; it does not reserve it.** The build
  requires `minAmountOut` when the saved `withdrawalSlippage` is not null, and
  refuses it when the policy is null.
- **Exit with the saved policy.** The position supplies the vault and mints,
  so a delisted strategy stays exitable. Never require the strategy to appear
  in today's catalog, and never guess a policy from a missing row.
- **If the build reports that the floor policy changed,** refresh it with
  your SDP contact before you retry.

At `finalized`, `tokenAmount` is the payout SDP observed. For independent
proof, check the customer's token balance onchain.

## Provider orders

A provider order takes an exact share amount and pays out after the provider
prices and settles it. Its preview may return `501`, which does not block the
build. No floor can bound a later price, so omit `minAmountOut` when the
policy is null.

Its `settlement` is `provider_order`: the movement stays `confirmed` until the
provider completes the order, so show it as pending until `finalized`. See
[How a movement settles](/docs/earn/concepts#how-a-movement-settles).

## Asynchronous withdrawals

A solver queue or an operator redemption creates a withdrawal request. The
request transaction moves shares, never the payout, so track the request until
it pays out or is canceled.

| | Solver queue | Operator redemption |
| --- | --- | --- |
| The request | Escrows shares. | Converts shares into an intermediate token and authorizes the operator to settle it. |
| Pays out | At a discount, when a solver fulfills it between maturity and the deadline. | At par, when the operator settles it. |
| Live terms to show | `queueAsset`: minimum shares, discount range, maturity, and deadline range. | `parRedemption`: minimum shares, `intermediateMint`, `assetMint`, and whether cancellation is allowed. |
| Send | `shares`, `discountBps`, and `deadlineSeconds`, each inside the live terms. `mechanism` defaults to `solverQueue`. | `mechanism: "operatorRedemption"` with either `shares` or `intermediateAmount` from a `parIntermediate` holding, never both. |
| Cancel | Only at `expiredCancelable`. Returns the escrowed shares. | While `pending`, if the live terms allow. Leaves the intermediate token, not the shares. |

- **A queue's discount is your customer's cost.** A larger `discountBps` makes
  a fill more likely, and the customer receives that much less.
- **A queue's deadline counts from maturity,** on the cluster's clock:
  `maturityTimestamp` and `deadlineTimestamp` are onchain Unix times. A longer
  `deadlineSeconds` keeps the shares escrowed longer if no solver fills the
  request.
- **Open requests leave the balance.** Their shares drop out of `shares` and
  earnings' `currentValue`, and earnings report `withdrawals_pending`. Show
  the request's `quotedAssets` as an expected payout.
- **A null `minimumShares` on a redemption** means the conversion rate is
  unavailable: the preview reports a blocking issue.

### Create a request

| Step | Request |
| --- | --- |
| Preview | [`POST /v1/earn/external-wallet/queued-withdrawal-previews`](/docs/reference/api/earn/create-earn-external-wallet-queued-withdrawal-preview) |
| Build | [`POST /v1/earn/external-wallet/withdrawal-request-transactions`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-request-transaction) |
| Submit | [`POST /v1/earn/external-wallet/withdrawal-requests`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-request), with an `Idempotency-Key` |

Resolve every `blockingIssues` entry, then build, sign, and submit as for an
instant withdrawal. Save the returned `withdrawalRequestId`, and keep the
signed request with its idempotency key until the request resolves: SDP
accepts it even after its build expires, as
[Retry safely](/docs/earn/integration-details#retry-safely) describes.

### Track a request

Poll [`GET /v1/earn/external-wallet/withdrawal-requests/{withdrawalRequestId}`](/docs/reference/api/earn/get-earn-external-wallet-withdrawal-request)
every minute or two. Status values spell it `cancelled`.

| Status | Meaning | What to show |
| --- | --- | --- |
| `creating` | SDP recorded the signed request; its chain outcome is unresolved. | Pending. |
| `pending` | Waiting for maturity or for the operator. | Pending, with the expected timing. |
| `fulfillable` | A solver may fulfill it now. | Pending. |
| `expiredCancelable` | The solver deadline passed without fulfillment. | Offer cancellation. |
| `cancelling` | A cancellation was submitted; a fulfillment can still race it. | Canceling. |
| `closedOrUnknown` | The request closed, and SDP has not yet proved a payout or a cancellation. | Pending; keep tracking. |
| `fulfilled` | SDP observed the payout. `assetsPaid` holds the amount. | Done. |
| `cancelled` | SDP observed the cancellation. | Canceled; refresh holdings. |
| `failed` | It did not happen: SDP decides that only after repeated checks find no trace of it. `failureReason` says why. | Failed. |

Only `fulfilled`, `cancelled`, and `failed` are final, and only `fulfilled`
pays out. Never credit `quotedAssets`, a request transaction, or a
cancellation as received funds. A request no solver takes stays `fulfillable`
until its deadline, then `expiredCancelable`, and its shares stay escrowed
until the customer cancels it.

On startup, restore every open request, reading every page:
[`GET /v1/earn/external-wallet/withdrawal-requests?ownerAddress=<wallet>&settled=false`](/docs/reference/api/earn/list-earn-external-wallet-withdrawal-requests).

<Callout type="warn">
Sign withdrawal requests and cancellations without broadcasting them, and
submit them through SDP promptly. If a wallet broadcasts one itself and SDP
first sees it after the build expires, SDP may not be able to track it.
</Callout>

### Cancel a request

Never offer a queue cancellation from a client clock: building one before
`expiredCancelable` returns `409 CONFLICT`. Refresh the request first, because
a fulfillment can race the cancellation.

| Step | Request |
| --- | --- |
| Build | [`POST /v1/earn/external-wallet/withdrawal-request-cancel-transactions`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-request-cancel-transaction) |
| Submit | [`POST /v1/earn/external-wallet/withdrawal-request-cancellations`](/docs/reference/api/earn/create-earn-external-wallet-withdrawal-request-cancellation) |

Both steps take `earn.manage` and a new `Idempotency-Key`, and they stay
available after production access is removed or new deposits are disabled.
Refresh holdings before another withdrawal.
