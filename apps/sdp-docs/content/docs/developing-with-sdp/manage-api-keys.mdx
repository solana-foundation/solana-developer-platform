---
title: Manage API keys
description: Create, rotate, and delete the API keys that authenticate your SDP API requests.
---

An API key authenticates an SDP API request. Each key belongs to a project, takes that project's
environment, and carries a role. A key can also carry finer controls. See
[Authentication](/docs/developing-with-sdp/authentication) for how SDP enforces each of those
layers.

SDP returns the full secret once, when you create the key and when you rotate it. SDP stores only a
salted hash and a display prefix. You cannot recover a lost key. You can only rotate it or replace
it.

Every key records `lastUsedAt`. Use that value to find a stale credential before you delete it.

## Key format

| Environment | Prefix | Solana cluster |
| --- | --- | --- |
| Sandbox | `sk_test_` | devnet |
| Production | `sk_live_` | mainnet |

## Roles

| Role | Description |
| --- | --- |
| `api_admin` | Full access, including custody operations and platform operations. |
| `api_developer` | Read and write access. It excludes custody actions. |
| `api_readonly` | Read-only access to every resource. |

A key can also carry explicit `permissions` that override the role's defaults. A key can hold only
the permissions its creator holds.

## Create a key

<Tabs items={["Dashboard", "API"]}>
<Tab value="Dashboard">

1. Select **API keys** in the sidebar. The list is empty until you create your first key.

   ![API keys page with no keys yet](/images/getting-started/api-keys-empty.png)

2. Select **New API key**.

3. Enter the key details:
   - **Name**. A descriptive label, for example "CI deploy key".
   - **Role**. **Admin**, **Developer**, or **Read only**.
   - **Wallet access**. **All wallets** or **Selected wallets**.
   - **Expiration (optional)**. A date and a time.

   ![Create API key modal](/images/getting-started/api-key-create.png)

4. Select **Continue**.

5. Review the summary, then select **Create key**.

   ![Review API key modal](/images/getting-started/api-key-review.png)

6. Select **Copy** on the **API key generated** dialog, and save the key. SDP does not show it
   again.

   ![API key generated modal showing the full key](/images/getting-started/api-key-generated.png)

7. Select **Dismiss**. The key now appears in the table with its prefix, role, environment, and
   status.

   ![API keys list with one active key](/images/getting-started/api-keys-list.png)

</Tab>
<Tab value="API">

<Tabs items={["curl", "TypeScript", "Java"]}>
<Tab value="curl">
```bash title="Terminal"
curl -X POST https://api.solana.com/v1/api-keys \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "CI deploy key",
    "role": "api_developer",
    "walletScope": "all",
    "expiresAt": "2027-12-31T23:59:59Z"
  }'
```
</Tab>
<Tab value="TypeScript">
```typescript title="create-api-key.ts"
const response = await fetch("https://api.solana.com/v1/api-keys", {
  method: "POST",
  headers: {
    "Authorization": "Bearer sk_test_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "CI deploy key",
    role: "api_developer",
    walletScope: "all",
    expiresAt: "2027-12-31T23:59:59Z",
  }),
});
const { data } = await response.json();
// data.apiKey.key — save this, only shown once
```
</Tab>
<Tab value="Java">
```java title="CreateApiKey.java"
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.solana.com/v1/api-keys"))
    .header("Authorization", "Bearer sk_test_...")
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString("""
        {
          "name": "CI deploy key",
          "role": "api_developer",
          "walletScope": "all",
          "expiresAt": "2027-12-31T23:59:59Z"
        }"""))
    .build();
```
</Tab>
</Tabs>

The new key belongs to the project of the key that created it, and takes that project's
environment. The request has no environment field.

The response includes the full `key` value. **Save it. SDP returns it only once.**

These fields are optional: `description`, `permissions` for finer overrides, `allowedIps` for IPv4,
IPv6, or CIDR ranges, `signingWalletId` and `signingWalletIds`, and `walletBindings` for per-wallet
permission lists.

</Tab>
</Tabs>

## Rotate a key

Rotation replaces the secret without a gap in availability. SDP creates a fresh key record that
copies the old key's role, permissions, IP allowlist, wallet bindings, and policy profiles. The old
key keeps working until its grace deadline.

Both keys are valid during the grace period. After the deadline, the old key fails with
`EXPIRED_API_KEY`.

<Tabs items={["Dashboard", "API"]}>
<Tab value="Dashboard">

1. Open the **Actions** menu next to the key in the API keys table.

2. Select **Rotate key (24h grace)**. The dashboard always uses a grace period of 24 hours. Use the
   API to set another value, from 0 to 168 hours.

   ![Actions dropdown showing Rotate key and Delete key options](/images/getting-started/api-key-rotate.png)

3. Copy the new key value from the **API key generated** dialog. SDP shows it once.

</Tab>
<Tab value="API">

<Tabs items={["curl", "TypeScript", "Java"]}>
<Tab value="curl">
```bash title="Terminal"
curl -X POST https://api.solana.com/v1/api-keys/key_abc123/rotate \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{ "gracePeriodHours": 24 }'
```
</Tab>
<Tab value="TypeScript">
```typescript title="rotate-api-key.ts"
const response = await fetch(
  "https://api.solana.com/v1/api-keys/key_abc123/rotate",
  {
    method: "POST",
    headers: {
      "Authorization": "Bearer sk_test_...",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ gracePeriodHours: 24 }),
  }
);
const { data } = await response.json();
// data.apiKey — the new key, only shown once
// data.previousKey.rotationDeadline — when the old key stops working
```
</Tab>
<Tab value="Java">
```java title="RotateApiKey.java"
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.solana.com/v1/api-keys/key_abc123/rotate"))
    .header("Authorization", "Bearer sk_test_...")
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString("""
        { "gracePeriodHours": 24 }"""))
    .build();
```
</Tab>
</Tabs>

`gracePeriodHours` accepts a value from 0 to 168. The default is 24. A key cannot rotate itself.
Authenticate the rotation with another key, or with a dashboard session.

</Tab>
</Tabs>

## Delete a key

<Tabs items={["Dashboard", "API"]}>
<Tab value="Dashboard">

1. Open the **Actions** menu next to the key.

2. Select **Delete key**.

3. Enter the key's name to confirm, then select **Delete key**.

The key stops working at once, and you cannot restore it. The row stays in the table.

</Tab>
<Tab value="API">

<Tabs items={["curl", "TypeScript", "Java"]}>
<Tab value="curl">
```bash title="Terminal"
curl -X DELETE https://api.solana.com/v1/api-keys/key_abc123 \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{ "confirmation": "CI deploy key" }'
```
</Tab>
<Tab value="TypeScript">
```typescript title="revoke-api-key.ts"
await fetch("https://api.solana.com/v1/api-keys/key_abc123", {
  method: "DELETE",
  headers: {
    "Authorization": "Bearer sk_test_...",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ confirmation: "CI deploy key" }),
});
```
</Tab>
<Tab value="Java">
```java title="RevokeApiKey.java"
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.solana.com/v1/api-keys/key_abc123"))
    .header("Authorization", "Bearer sk_test_...")
    .header("Content-Type", "application/json")
    .method("DELETE", HttpRequest.BodyPublishers.ofString("""
        { "confirmation": "CI deploy key" }"""))
    .build();
```
</Tab>
</Tabs>

The `confirmation` field must match the key's **name**.

The deletion takes effect at once, and you cannot undo it. The call is idempotent, so a second call
on the same key also succeeds. As with rotation, a key cannot delete itself.

</Tab>
</Tabs>
