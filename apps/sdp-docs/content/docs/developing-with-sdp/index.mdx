SDP gives you two interfaces: the dashboard and the REST API. Both run against the same backend,
and both enforce the same permissions, policies, and audit records.

- **The dashboard** is a browser application for setup, token management, and compliance
  operations. Sign in with an email address, a Google account, or a GitHub account.
- **The REST API** is for backend integrations. Every route reads an API key from the
  `Authorization` header.

The API covers everything the dashboard does. Build against the API for automation and
integrations. Use the dashboard to set up your organization, inspect state, and run a single
operation by hand.

## Environments

The environment belongs to the **project**, not to an individual request. Every tenant resource and
every API key belongs to a project, and takes that project's environment.

| Environment  | Solana cluster | API key prefix |
| ------------ | -------------- | -------------- |
| `sandbox`    | devnet         | `sk_test_`     |
| `production` | mainnet        | `sk_live_`     |

Both environments have the same routes. Develop and test your integration against a sandbox
project. To move to production, change the API key.

## Response conventions

Every successful response wraps its payload in a `data` envelope, next to the metadata of the
request:

```json
{
  "data": { ... },
  "meta": { "requestId": "req_...", "timestamp": "2027-07-31T12:00:00.000Z" }
}
```

An error returns a `code` for your code to read, and a `message` for a person to read:

```json
{
  "error": { "code": "INVALID_API_KEY", "message": "Invalid API key" }
}
```

Include the `requestId` when you report a problem. It links your request to the internal traces and
audit records.

## Execution model

SDP runs a custody operation in three steps. SDP builds the transaction, signs it with the
configured custody wallet, and submits it.
