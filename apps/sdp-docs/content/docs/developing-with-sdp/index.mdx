SDP exposes two interfaces that operate over the same backend and enforce the same permissions, policies, and audit trails:

- **Dashboard** — browser-based UI for setup, token management, and compliance operations. Sign in with email, Google, or GitHub.
- **REST API:** programmatic access for backend integrations. Routes authenticate with an API key in the `Authorization` header.

Everything the dashboard does is available through the API. Build against the API for automation and integrations; use the dashboard to set up your organization, inspect state, and perform one-off operations.

## Environments

The environment is a property of the **project**, not of individual requests. Every organization has exactly two projects, one sandbox and one production. Every tenant resource and API key belongs to one of them and inherits that project's environment.

| Project      | Network      | API key prefix |
| ------------ | ------------ | -------------- |
| `sandbox`    | devnet       | `sk_test_`     |
| `production` | mainnet-beta | `sk_live_`     |

Both environments use the same base URL, `https://api.solana.com`, and the same route shapes. The API key you send decides the project, and with it the environment. Develop and test against the sandbox project, then move to production with a production key.

Resources don't carry over between projects: the production project has its own wallets, tokens, and API keys, so set those up there before you go live. Production access is enabled per organization; see [Set Up Your Organization & Projects](/docs/guides/setup-organization).

## Response conventions

Every successful response wraps its payload in a `data` envelope with request metadata:

```json
{
  "data": { ... },
  "meta": { "requestId": "req_...", "timestamp": "2026-07-31T12:00:00.000Z" }
}
```

Errors return a machine-readable `code` alongside a human-readable `message`:

```json
{
  "error": { "code": "INVALID_API_KEY", "message": "Invalid API key" }
}
```

Include the `requestId` when reporting an issue — it links your request to our internal traces and audit records.

## Execution model

SDP executes custody operations by building, signing, and submitting with the configured custody wallet.
