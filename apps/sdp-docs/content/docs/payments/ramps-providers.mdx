title: Ramp providers
description: The capability matrix, the credentials, and the per-provider notes for the seven SDP ramp providers.

SDP integrates seven ramp providers: MoonPay, Lightspark, BVNK, MoneyGram, Coinbase, Mural, and
Stripe.

An administrator configures each provider with credentials on the SDP API deployment. Each
organization is then entitled to some or all of the configured providers. See
[Provider gating](#provider-gating).

The same `provider` string on `POST /v1/payments/ramps/onramp/quote` and
`POST /v1/payments/ramps/offramp/quote` selects between them.

## Sandbox vs production selection

SDP chooses the sandbox mode or the production mode per request, not at deployment time.

- A deployment that is not a production deployment always uses the sandbox credentials.
- On a production deployment, the environment of the calling API key picks the mode. An `sk_test_`
  key uses sandbox. An `sk_live_` key uses production.

Configure both credential pairs for any provider that you want to serve test traffic and live
traffic on the same deployment. MoonPay, Lightspark, BVNK, and Mural each read a separate sandbox
pair and production pair this way.

Coinbase and Stripe use a single credential pair, whichever mode SDP resolves. See their sections
below. MoneyGram has sandbox credentials only today.

## Capability matrix

| Provider | Onramp | Offramp | Sandbox | Delivery mode | Notes |
| --- | --- | --- | --- | --- | --- |
| MoonPay | ✓ | ✓ | ✓ | `hosted` | SDP selects sandbox or production per request. See [Sandbox vs production selection](#sandbox-vs-production-selection). |
| Lightspark | ✓ | ✓ | ✓ | `manual_instructions` | Grid API. The same per-request sandbox and production selection as MoonPay. |
| BVNK | ✓ | ✓ | ✓ | `manual_instructions` | Hawk authentication. SDP builds the compliance party details from the counterparty record, not from the request. |
| MoneyGram | ✓ (sandbox only) | ✓ (sandbox only) | ✓ | `session_widget` | A sandbox-only pilot integration. There is no production credential path yet. |
| Coinbase | ✓ (sandbox only) | ✗ | ✓ | `hosted` | Onramp only. Rate estimates work in production. Order creation works in sandbox only. |
| Mural | ✓ | Estimate only | ✓ | `manual_instructions` | Onramp only for a quote. The offramp rate estimate works, and offramp quote creation is not implemented yet. |
| Stripe | ✓ | ✗ | ✓ (shared credentials) | `session_widget` | Onramp only. There are no separate sandbox credentials. Supply a Stripe test-mode secret key. |

## MoonPay

| Variable | Required | Notes |
| --- | --- | --- |
| `MOONPAY_API_KEY` | For a production request | Production API key. |
| `MOONPAY_SECRET_KEY` | For a production request | Production secret. SDP signs the onramp and offramp URLs with it. Pair it with `MOONPAY_API_KEY`. |
| `MOONPAY_SANDBOX_API_KEY` | For a sandbox request | Sandbox API key. |
| `MOONPAY_SANDBOX_SECRET_KEY` | For a sandbox request | Sandbox secret. Pair it with `MOONPAY_SANDBOX_API_KEY`. |
| `MOONPAY_ONRAMP_URL` | Never | Overrides the onramp host. It defaults to MoonPay's standard URLs. The sandbox or production choice follows the [per-request rule](#sandbox-vs-production-selection). |
| `MOONPAY_OFFRAMP_URL` | Never | The same override for the offramp host. |

MoonPay normalizes its own currency codes internally. SDP accepts the canonical asset rails, such
as `usdc.solana`, and maps them to MoonPay's code, such as `usdc_sol`.

## Lightspark

| Variable | Required | Notes |
| --- | --- | --- |
| `LIGHTSPARK_GRID_CLIENT_ID` | For a production request | Production Grid API client identifier. |
| `LIGHTSPARK_GRID_CLIENT_SECRET` | For a production request | Production Grid API client secret. |
| `LIGHTSPARK_GRID_SANDBOX_CLIENT_ID` | For a sandbox request | Sandbox Grid API client identifier. |
| `LIGHTSPARK_GRID_SANDBOX_CLIENT_SECRET` | For a sandbox request | Sandbox Grid API client secret. |

SDP integrates Lightspark against the Grid API at
`https://api.lightspark.com/grid/2025-10-13`. The sandbox or production choice follows the
[per-request rule](#sandbox-vs-production-selection).

`destinationCustodyWalletId` and `sourceCustodyWalletId` are your own custody wallet, as with
every other provider. SDP resolves the Lightspark customer ID and payout account on the server,
from the counterparty's provider requirements. You do not pass them on the quote request.

A counterparty no longer stores identity fields or an email field. An existing Lightspark customer
still resolves from the provider data. Creating a first-time customer currently fails with a clear
error, until just-in-time identity collection is connected.

A Lightspark quote always returns `deliveryMode: "manual_instructions"`. The response carries
funding instructions to display to the payer, not a redirect URL.

## BVNK

| Variable | Required | Notes |
| --- | --- | --- |
| `BVNK_WALLET_ID` | For a production request | Production BVNK-side wallet used for settlement. |
| `BVNK_HAWK_AUTH_ID` | For a production request | Production Hawk auth id. Pair it with `BVNK_HAWK_SECRET_KEY`. |
| `BVNK_HAWK_SECRET_KEY` | For a production request | Production Hawk secret key. |
| `BVNK_SANDBOX_WALLET_ID` | For a sandbox request | Sandbox BVNK wallet. |
| `BVNK_SANDBOX_HAWK_AUTH_ID` | For a sandbox request | Sandbox Hawk auth id. |
| `BVNK_SANDBOX_HAWK_SECRET_KEY` | For a sandbox request | Sandbox Hawk secret key. |

BVNK uses Hawk authentication. SDP does not support bearer-token authentication for BVNK.

BVNK shares travel-rule and compliance data, so it requires party details such as a name and an
address. A counterparty no longer stores those fields. Customer creation, payment-rule creation,
and the offramp compliance payload therefore fail today with a clear error, at the seam where
just-in-time collection will go.

A BVNK quote always returns `deliveryMode: "manual_instructions"`. The response carries
funding-account details to display to the payer.

## MoneyGram

| Variable | Required | Notes |
| --- | --- | --- |
| `MONEYGRAM_SANDBOX_PUBLIC_KEY` | For every MoneyGram request | Sandbox public key. SDP sends it as `x-api-key` on the asset-rail discovery call that lists currencies. |
| `MONEYGRAM_SANDBOX_SECRET_KEY` | For every MoneyGram request | Sandbox secret key. SDP sends it as `x-api-key` on the estimate, quote, and session calls. |

MoneyGram is a sandbox-only pilot integration today. The client always calls MoneyGram's sandbox
host, and it throws an error when a request resolves to production. There is no production
credential pair to configure yet.

A MoneyGram quote always returns `deliveryMode: "session_widget"`. Onramp and offramp both create
a session against the same endpoint. Both return a `widgetUrl`, with `mode=on-ramp` or
`mode=off-ramp`, and a short-lived `sessionToken` to mount.

MoneyGram needs no provider requirements collection. SDP treats every counterparty as ready.

## Coinbase

| Variable | Required | Notes |
| --- | --- | --- |
| `COINBASE_CDP_API_KEY_ID` | For every Coinbase request | CDP Secret API Key id. SDP uses the same key for sandbox and for production. Sandbox is flagged per request, not by a separate credential. |
| `COINBASE_CDP_API_KEY_SECRET` | For every Coinbase request | CDP Secret API Key secret. Pair it with `COINBASE_CDP_API_KEY_ID`. SDP signs a per-request JWT with it. |

Coinbase is onramp-only. Both `estimateOfframp` and `createOfframpQuote` reject the call with
"Coinbase Onramp does not support off-ramp."

A Coinbase onramp quote always returns `deliveryMode: "hosted"`. SDP creates a guest-checkout
Apple Pay order and returns its payment link as `hostedUrl`.

Order creation, which is the quote step, works in sandbox only today. It requires a buyer
agreement and phone-OTP attestation timestamps that the SDP production flow does not collect yet.
A non-sandbox request therefore fails loudly, rather than sending a false attestation. Rate
estimates carry no such restriction, and they work in both modes.

Coinbase also requires an email value and a phone value. Quote creation currently fails at the
seam where just-in-time collection will go.

## Mural

| Variable | Required | Notes |
| --- | --- | --- |
| `MURAL_PAY_API_KEY` | For a production request | Production API key for the organization, account, and payin calls. |
| `MURAL_PAY_SANDBOX_API_KEY` | For a sandbox request | The sandbox equivalent. |
| `MURAL_PAY_TRANSFER_API_KEY` | For a production request | Production transfer-scoped key. SDP sends it as a separate header on payout-execute calls. |
| `MURAL_PAY_SANDBOX_TRANSFER_API_KEY` | For a sandbox request | The sandbox equivalent of the transfer key. |

Mural onramp accepts a business counterparty only. It does not accept the individual entity type.

A Mural quote requires that the counterparty's Mural organization and payin account already exist.
You create them through provider requirements onboarding, which covers organization creation,
terms-of-service acceptance, and verification.

The quote returns `deliveryMode: "manual_instructions"`, built from that account's active payin
method. The quote step itself makes no live call to Mural.

An existing Mural organization still resolves from the provider data. Creating a first-time
organization currently fails with a clear error, until just-in-time identity collection is
connected.

Offramp rate estimates work today, through a real call to Mural's fees endpoint. Offramp quote
creation always throws, because it is not implemented yet.

## Stripe

| Variable | Required | Notes |
| --- | --- | --- |
| `STRIPE_SECRET_KEY` | For every Stripe request | Secret key. SDP sends it as the username on HTTP Basic authentication. One key serves both modes. Use an `sk_test_…` key for sandbox and an `sk_live_…` key for production. |
| `STRIPE_PUBLISHABLE_KEY` | For every Stripe request | Publishable key. SDP echoes it back on the quote, so that your client can mount the onramp session. |

Stripe is onramp-only. Both `estimateOfframp` and `createOfframpQuote` reject the call as
unsupported. Stripe onramp also accepts only `usdc.solana` and `sol.solana` as destination assets.

A Stripe quote always returns `deliveryMode: "session_widget"`. It carries a `clientSecret` and a
`publishableKey` to mount Stripe's crypto onramp session, plus an optional `redirectUrl`.

## Provider gating

An organization can be restricted to a subset of providers, even when the credentials for all
seven are populated. This is
[**Provider Availability**](/docs/reference/provider-onboarding): a provider must be configured
for the deployment and either generally available or manually activated for the organization.

SDP checks this on every ramp call. When the organization does not have availability for the
requested provider, the call returns an error.

To activate or change provider availability for a deployment, see
[Provider onboarding](/docs/reference/provider-onboarding).

## Choosing a provider

| Need | Lean towards |
| --- | --- |
| Fastest sandbox iteration | MoonPay or BVNK. |
| Travel-rule and compliance party metadata | BVNK. |
| Lightning-aware fiat settlement | Lightspark. |
| Broadest payment-method coverage | MoonPay, depending on the corridor. |
| Business-entity onramp counterparties | Mural, its only supported entity type. |
| An onramp UI embedded as a widget or session | MoneyGram, in sandbox only, or Stripe. |
| Onramp only, with no offramp | Coinbase or Stripe. |

For self-hosted deployments where only a subset of providers will ever be configured, see
[Providers optional for self-hosted SDP](/docs/reference/provider-onboarding) — SDP supports
running with any single provider active.
