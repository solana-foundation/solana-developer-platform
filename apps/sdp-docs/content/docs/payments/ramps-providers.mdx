SDP integrates the ramp providers in the matrix below. They are configured at the organization level via environment variables on the SDP API deployment; the same `provider` string on `POST /v1/payments/ramps/onramp/quote` and `POST /v1/payments/ramps/offramp/quote` selects between them.

## Sandbox vs production selection

The sandbox/production mode is chosen **per request**, not at deployment time:

- Non-production SDP deployments (`ENVIRONMENT !== "production"`) always use sandbox credentials.
- In production deployments, the calling API key's environment picks the mode — `sk_test_` keys use sandbox, `sk_live_` use production.

Configure both credential pairs for any provider you want to expose to test and live traffic on the same deployment, when the provider reads separate sandbox and production credentials; each provider's page says which.

## Provider gating

Even when every provider's env vars are populated, an org can be restricted to a subset. This is [**Provider Availability**](/docs/reference/provider-onboarding): a provider must be configured for the deployment and either generally available or manually activated for the organization. SDP checks this on every ramp call: if the org lacks availability for the requested provider, the call returns an error. To activate or change provider availability for a deployment, see [Provider onboarding](/docs/reference/provider-onboarding).

## Choosing a provider

The **Best for** column of the capability matrix compares the providers this deployment offers.

For self-hosted deployments where only a subset of providers will ever be configured, see [Providers optional for self-hosted SDP](/docs/reference/provider-onboarding) — SDP supports running with any single provider active.
