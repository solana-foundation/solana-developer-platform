SDP integrates the ramp providers in the matrix below. The SDP API deployment configures each one with environment variables, and the `provider` field on a quote picks between them.

## Sandbox vs production selection

The project's environment picks the mode for every request: a Sandbox project uses a provider's sandbox credentials, a Production project its production ones. Each key is named `<PROVIDER>_<MODE>_<ROLE>`, with `MODE` either `SANDBOX` or `PRODUCTION`. A provider whose keys for a mode are missing, or are the other mode's, answers `503 PROVIDER_NOT_CONFIGURED` in that mode. A deployment can configure any subset of providers. Each provider's page lists the keys it reads.

## Provider gating

A provider is usable when its **Provider Availability** allows it: the deployment configures it, and the organization may use it. Ramp providers are generally available, so every organization can use a configured one unless the deployment's operator turns it off for that organization.

SDP checks this on every estimate and quote. A quote with a provider the organization can't use returns `403 FORBIDDEN`, and `details.reason` says why: `provider_not_in_release_channel`, `provider_not_offered`, or `provider_not_entitled`. An estimate reports the refusal in that provider's entry instead.
