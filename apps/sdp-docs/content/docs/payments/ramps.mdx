---
title: Ramps
description: Fiat on-ramps and off-ramps. Let users buy crypto with fiat, or cash out from a wallet, through SDP.
---

SDP puts several ramp providers behind one set of endpoints. You discover which corridors are available, price the conversion, then request a quote that returns whatever the chosen provider needs to collect payment.

Two things are worth knowing before you start.

**Ramps are a two-step flow.** `estimate` prices a conversion and commits you to nothing. `quote` creates the actual ramp and returns provider-specific payment details. There is no single call that does both.

**Every quote requires a counterparty.** The person or business on the other side of the conversion must exist as a counterparty and must have cleared that provider's requirements for the corridor you are using. A quote for an unprovisioned counterparty is rejected.

For per-provider configuration, see [Ramp providers](/docs/payments/ramps-providers).

## Discover available corridors

A corridor is a fiat currency paired with a crypto rail, for example USD to `usdc.solana`. Not every combination exists, and which providers serve a corridor varies by corridor.

```bash
curl "https://api.solana.com/v1/payments/ramps/onramp/currency" \
  -H "Authorization: Bearer sk_test_..."
```

```json
{
  "data": {
    "currencies": {
      "sources": ["ARS", "AUD", "BRL", "CAD", "EUR", "GBP", "NGN", "USD", "..."],
      "destinations": ["pyusd.solana", "sol.solana", "usdc.solana", "usdg.solana", "usdt.solana"]
    },
    "pairs": [
      { "source": "ARS", "dest": "usdc.solana", "providers": ["mural"] },
      { "source": "USD", "dest": "usdc.solana", "providers": ["lightspark", "bvnk", "moneygram", "coinbase", "mural", "stripe"] }
    ]
  }
}
```

<Callout type="warn">
Read `pairs`, not the cross product of `sources` and `destinations`. Most combinations of the two arrays are not real corridors. A currency appearing in `sources` only means some corridor uses it, not that it pairs with the rail you want.
</Callout>

Use `GET /v1/payments/ramps/offramp/currency` for the reverse direction. Both accept optional `source`, `dest` and `provider` query parameters to narrow the result.

## Price the conversion

`estimate` needs no counterparty and creates nothing. It asks every provider serving the corridor and returns all of their answers.

<Tabs items={["curl", "TypeScript"]}>
<Tab value="curl">
```bash
curl -X POST https://api.solana.com/v1/payments/ramps/onramp/estimate \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "assetRail": "usdc.solana",
    "fiatCurrency": "USD",
    "fiatAmount": "100.00"
  }'
```
</Tab>
<Tab value="TypeScript">
```typescript
const response = await fetch(
  "https://api.solana.com/v1/payments/ramps/onramp/estimate",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer sk_test_...",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      assetRail: "usdc.solana",
      fiatCurrency: "USD",
      fiatAmount: "100.00",
    }),
  }
);
const { data } = await response.json();
```
</Tab>
</Tabs>

The response is an array with one entry per provider, and entries fail independently:

```json
{
  "data": {
    "estimates": [
      {
        "provider": "moneygram",
        "status": "ok",
        "estimate": {
          "provider": "moneygram",
          "direction": "onramp",
          "fiatCurrency": "USD",
          "assetRail": "usdc.solana",
          "fiatAmount": "104.50",
          "cryptoAmount": "100.000000",
          "exchangeRate": "1",
          "fees": { "currency": "USD", "total": "4.50", "provider": "4.50" }
        }
      },
      {
        "provider": "bvnk",
        "status": "error",
        "error": "BVNK request failed with status 404"
      }
    ]
  }
}
```

<Callout type="warn">
Handle `estimates` as a partial result. A provider can be registered, serve the corridor, and still return `status: "error"` on any given call. Filter to `status === "ok"` before comparing prices, and do not assume a specific provider will be present.
</Callout>

`POST /v1/payments/ramps/offramp/estimate` takes the same shape with `cryptoAmount` in place of `fiatAmount`.

### Estimate request fields

| Field | Required | Notes |
| --- | --- | --- |
| `assetRail` | yes | Crypto rail, for example `usdc.solana`. Use a value from the `destinations` array. The quote step names the same asset differently, as a bare `cryptoToken` symbol, so you cannot forward this value straight through. |
| `fiatCurrency` | yes | ISO 4217 code from the `sources` array. |
| `fiatAmount` | on-ramp | Decimal string greater than zero. |
| `cryptoAmount` | off-ramp | Decimal string greater than zero. |

## Provision the counterparty

Before a quote will succeed, the counterparty needs to satisfy that provider's requirements for the corridor. Requirements are corridor-specific, so the currency and rail are part of the request, not just the provider.

```bash
curl "https://api.solana.com/v1/counterparties/$COUNTERPARTY_ID/requirements\
?provider=lightspark&direction=offramp&cryptoToken=USDC&fiatCurrency=USD" \
  -H "Authorization: Bearer sk_test_..."
```

A counterparty that still owes information returns `status: "collect"` and describes exactly what to gather:

```json
{
  "data": {
    "provider": "lightspark",
    "direction": "offramp",
    "status": "collect",
    "fields": [
      {
        "kind": "select",
        "key": "paymentRails",
        "label": "Payment rail",
        "required": true,
        "options": [{ "value": "ACH", "label": "ACH" }, { "value": "WIRE", "label": "Wire" }]
      },
      {
        "kind": "text",
        "key": "routingNumber",
        "label": "Routing number",
        "required": true,
        "pattern": "^[0-9]{9}$",
        "placeholder": "021000021"
      }
    ]
  }
}
```

Render those fields, then submit what you collected back to the same path:

```bash
curl -X POST "https://api.solana.com/v1/counterparties/$COUNTERPARTY_ID/requirements" \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "lightspark",
    "direction": "offramp",
    "cryptoToken": "USDC",
    "fiatCurrency": "USD",
    "collectedData": {
      "paymentRails": "ACH",
      "routingNumber": "021000021",
      "accountNumber": "000123456789"
    }
  }'
```

A counterparty that owes nothing returns `status: "ready"`, and you can quote. On-ramp requirements additionally require `destinationWallet` on the request.

## Request a quote

A quote creates the ramp and returns what the provider needs from the end user.

<Tabs items={["curl", "TypeScript"]}>
<Tab value="curl">
```bash
curl -X POST https://api.solana.com/v1/payments/ramps/onramp/quote \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "moneygram",
    "counterpartyId": "counterparty_...",
    "destinationWallet": "privy_...",
    "cryptoToken": "USDC",
    "fiatCurrency": "USD",
    "fiatAmount": "100.00"
  }'
```
</Tab>
<Tab value="TypeScript">
```typescript
const response = await fetch(
  "https://api.solana.com/v1/payments/ramps/onramp/quote",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer sk_test_...",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      provider: "moneygram",
      counterpartyId: "counterparty_...",
      destinationWallet: "privy_...",
      cryptoToken: "USDC",
      fiatCurrency: "USD",
      fiatAmount: "100.00",
    }),
  }
);
const { data } = await response.json();
// data.quote.deliveryMode tells you what to do next
```
</Tab>
</Tabs>

### Quote request fields

| Field | Required | Notes |
| --- | --- | --- |
| `provider` | yes | Pick one from the corridor's `providers` list. SDP does not choose for you. |
| `counterpartyId` | yes | Must be `ready` for this provider and corridor. |
| `destinationWallet` | on-ramp | The `walletId` from `GET /v1/wallets`, for example `privy_...`, or that wallet's public key. Either must resolve to a wallet in your list. An unrelated Solana address is rejected with `must reference an SDP wallet`. Note this is looser than `POST /v1/payments/transfers`, where only the `walletId` is accepted. |
| `sourceWallet` | off-ramp | The wallet you are cashing out from, same forms and the same restriction. |
| `cryptoToken` | yes | Token **symbol**, for example `USDC`. Not the `assetRail` you passed to `estimate`. Take the part before the dot and upper-case it, so `usdc.solana` becomes `USDC`. Passing the rail form is rejected with a 400 on `cryptoToken`. |
| `fiatCurrency` | on-ramp, and in practice on off-ramp | Required on on-ramp. The off-ramp schema marks it optional, but Lightspark and BVNK both reject an off-ramp quote without it, so treat it as required unless you have checked your provider. |
| `fiatAmount` | on-ramp | Decimal string. |
| `cryptoAmount` | off-ramp | Decimal string. |
| `redirectUrl` | no | Where the provider returns the user after a hosted flow. |
| `rampsMemo` | no | Key-value metadata carried on the ramp. |
| `domain` | no | Coinbase only. Browser origin host for the Apple Pay payment link. |

## Handle the delivery mode

Every quote carries a `deliveryMode`. It tells you how the end user completes payment, and it determines which other fields are present. Your integration branches on this field, not on the provider name.

### `manual_instructions`

The user pays from their own bank or wallet. `paymentInstructions` describes where to send funds. Display it and wait for settlement.

```json
{
  "data": {
    "quote": {
      "provider": "lightspark",
      "id": "Quote:019ff0a8-...",
      "status": "pending",
      "deliveryMode": "manual_instructions",
      "paymentInstructions": [
        {
          "provider": "lightspark",
          "kind": "crypto_deposit",
          "destinationAddress": "8neePb9XJ2vB4vnLG5uSdhw8XNfnUhB1rebCYKizdk11",
          "cryptoCurrency": "USDC",
          "network": "SOLANA"
        }
      ],
      "exchangeRate": 1
    }
  }
}
```

### `hosted`

The provider runs the whole payment journey on its own page. Send the user to `hostedUrl`.

```json
{
  "data": {
    "quote": {
      "provider": "moonpay",
      "id": "ramp_quote_589ffbef-...",
      "status": "pending",
      "deliveryMode": "hosted",
      "hostedUrl": "https://buy-sandbox.moonpay.com/?apiKey=pk_test_...&baseCurrencyAmount=100.00"
    }
  }
}
```

### `session_widget`

The provider's widget is embedded in your own interface, authenticated by a short-lived credential.

```json
{
  "data": {
    "quote": {
      "provider": "moneygram",
      "id": "05e1a087-...",
      "status": "pending",
      "deliveryMode": "session_widget",
      "sessionToken": "eyJhbGciOiJIUzI1NiJ9...",
      "sessionId": "05e1a087-...",
      "widgetUrl": "https://playground.xramps.moneygram.com/sdk/widget.html?mode=on-ramp"
    }
  }
}
```

`sessionToken` and `clientSecret` are bearer credentials. Pass them to the widget and do not log or persist them. MoneyGram's token carries a one hour expiry in its `exp` claim, and Stripe's `clientSecret` should be treated as similarly short-lived.

Request the quote at the point the user is ready to pay rather than earlier in your flow, because the quote expires independently of the credential. Lightspark returns an optional `expiresAt` marking when its locked rate lapses, and an expired quote can no longer be cancelled. See [Cancel a ramp](#cancel-a-ramp).

Which providers use which mode is not fixed. Read `deliveryMode` from the response rather than mapping it from the provider name, and treat an unrecognised value as unsupported instead of guessing.

## Observe the ramp

A quote creates a transfer record. It appears in `GET /v1/payments/transfers` with `type` of `onramp` or `offramp`, and it is the surface to reconcile against.

```json
{
  "id": "xfr_9ff1017b-2c1f-4d99-9c51-edba356aee56",
  "type": "offramp",
  "direction": "outbound",
  "status": "canceled",
  "signature": null,
  "walletId": "privy_..."
}
```

<Callout>
`signature` is populated only when the provider settles on Solana. Some providers complete a ramp entirely off-chain, so a `completed` transfer with a null `signature` is expected for them rather than a failure. Use `signature` to tell an on-chain settlement from a provider-attested one.
</Callout>

See [Index transfers](/docs/payments/accept-indexing) for querying and pagination.

## Cancel a ramp

Cancel an unsettled ramp with the provider and its quote identifier.

```bash
curl -X POST https://api.solana.com/v1/payments/ramps/transfers/cancel \
  -H "Authorization: Bearer sk_test_..." \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "lightspark",
    "providerReference": "Quote:019ff0c3-..."
  }'
```

The response returns the transfer with `status: "canceled"`.

Quotes expire. Cancelling one that has already lapsed returns `400` with `Transfer can no longer be canceled (status: expired)`. Treat that as a terminal state, not a retryable error.

## Test without moving money

`POST /v1/payments/ramps/sandbox/simulate` drives a sandbox ramp through its states so you can exercise your settlement handling without a real payment. Sandbox and production are selected per request from the calling key: `sk_test_` keys use provider sandboxes, `sk_live_` keys use production.
