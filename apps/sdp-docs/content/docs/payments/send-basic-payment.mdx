SDP handles token transfers through its Payments API. A basic payment moves tokens from a custody
wallet you control to any Solana wallet address.

`sourceCustodyWalletId` is the SDP wallet `id` (`cwlt_…`). `GET /v1/wallets` returns it. SDP
resolves it on the server from the caller's list of custody wallets.

`destination` is the recipient's Solana wallet address, also called the owner address. For SPL
token transfers, SDP derives the associated token account from this address. SDP creates that
account if it does not exist.

Pass the wallet address. Do not pass a token account address.

You can send a transfer from the dashboard or from the API.

## Prerequisites

- A deployed token with minted supply.
- A custody wallet to use as `sourceCustodyWalletId`. It needs a custody signer configured, so that
  SDP can sign and submit the transaction.
- An API key with both the `payments:write` and `wallets:read` permissions. The route layer for
  `POST /v1/payments/transfers` checks for that pair. SDP then re-checks the source wallet against
  the wallet scope of the key's `payments:write` permission, so that scope must include the source
  wallet.

Enter the following values:

- **Source wallet.** A wallet you control in SDP.
- **Amount.** Display units, for example `0.5`.
- **Asset.** One of your deployed tokens.
- **Destination.** Any valid Solana wallet address.
- **Memo (optional).** A note that SDP records with the transfer.

</Tab>
<Tab value="API">

Build the request body:

```typescript title="transfer-request.ts"
const body = {
  sourceCustodyWalletId: "cwlt_123",    // `id` from GET /v1/wallets
  destination: "7xKXz...9fGh",         // recipient wallet (owner) address
  token: "9aBCd...4eEf",               // onchain mint address
  amount: "100.00",                    // human-readable units
  memo: "Payment for invoice #1234",
};
```

`token` is the mint address that the deploy step returned. It is not the SDP token ID.
`destination` is the wallet address, and SDP derives the associated token account from it.

## Deduplication

Send one stable `Idempotency-Key` for each logical payment, and reuse that key for network
retries.

An identical request for the same exact `sourceCustodyWalletId` returns the original transfer. If
you reuse the key with a different payload, or with a different wallet, the API returns `409`. A
request with no key creates a new transfer intent.

Persist the returned `Transfer.id` as your local primary key. Once SDP sets the onchain
`signature`, that value is also unique across SDP transfers. You can use it to deduplicate records
across SDP and another chain indexer.

See [Payouts and disbursements](/docs/payments/send-payouts#dedup-and-retries) for the same pattern
applied to batched outbound flows.
