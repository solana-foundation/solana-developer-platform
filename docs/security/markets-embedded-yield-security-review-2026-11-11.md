# Markets Embedded Yield security review — 2026-11-11

Owner: `@solana-foundation/sdp-maintainers`

Scope: the dashboard's Embedded Yield surface (`/dashboard/[projectId]/markets/embedded-yield` and its `configure` page) and every server it reaches, reviewed for loss-of-funds and data-exfiltration risks. Baseline `main` at `24ebe11f4`. Method: full read of the page's dependency closure — page components, the data seam (`earn-program-data.ts`), the BFF proxies under `app/api/dashboard/markets/earn/`, the API-side external-wallet handlers and build/verify/broadcast service, and the auth middleware — plus sink sweeps (`dangerouslySetInnerHTML`, `eval`, `innerHTML`, `window.open`, external `fetch`, `postMessage`, Web Storage, clipboard, cookies) across the markets subtree. A unit test is the only place a sink hit was expected to appear; every sweep hit was a test or a defended boundary.

## Result

No medium-or-higher finding. No code change ships with this record; it documents what was verified and why the deliberate departures from convention are intended.

## Verified invariants

| Surface                            | Verified                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication and project scoping | Every request carries a Clerk JWT; `projectContextMiddleware` requires a `project_members` row and every Earn query filters by organization, project and environment. Routes declare one action via `requireAction`; API keys hold explicit grants and can never hold administration or any `configure`.                                                              |
| BFF proxies                        | `proxyToSdpApi` never copies an inbound header (the caller's credential travels as its own bearer token), forwards only an opt-in `Idempotency-Key`, sets no CORS header, and answers with `Cache-Control: private, no-store` plus `Vary: x-project-id`.                                                                                                              |
| Per-customer data (EARN-028)       | The summary proxy refuses every query parameter and hardcodes `includeOwnerAddresses=true&includePositions=true`, so the one surface that may read per-customer wallet addresses is the project member's own dashboard view. The per-owner route validates its path segment as a base58 Solana address.                                                               |
| Response boundaries                | Every dashboard seam parses its envelope with a zod schema (`earnExternalWalletPositionSummarySchema` among them); a drifted contract fails the fetch instead of crashing the render path. Money is a decimal string end to end — no `Number` cast anywhere in the closure — and an absent `tokenValue` renders as unavailable, never as zero.                        |
| Funds movement                     | External-wallet deposits and withdrawals run `validate → authorize(fn) → idempotent()`; the submit path re-derives the expected message bytes, requires byte equality with the transaction it built, and ed25519-verifies every signature before broadcast (`verifySignedExternalWalletTransaction`). No route in the closure signs or broadcasts anything by itself. |
| CSRF                               | `rejectCrossSiteWrite` (EARN-021, PRO-1865) gates every write under `/api/dashboard(.*)` and every Server Action on `Origin` / `Sec-Fetch-Site` / session-cookie evidence.                                                                                                                                                                                            |
| Cache and session isolation        | The workspace `<SWRConfig>` keys its cache by session, organization and project (`swrScopeKey`) and rebuilds the map per mount, so one project's data cannot answer another project's key.                                                                                                                                                                            |
| Injection and link-out             | No markup sink in the closure; explorer URLs build with `encodeURIComponent` and open `noopener,noreferrer`; snippet interpolation passes a guarded `snippetToleranceBps` and the snippet tests assert a hostile value cannot break out of the generated code.                                                                                                        |
| Storage                            | `sessionStorage` holds only versioned idempotency and preference keys — never a credential; the dashboard's generated API keys stay memory-only (HOO-989 rule). The one clipboard write is a user-initiated copy of an address already rendered.                                                                                                                      |

## Deliberate departures, confirmed intended

- **External-wallet submits are not `requestGate`d.** The owner's ed25519 signature is the authorization; the server cannot act without it and holds no signing sink for these flows.
- **The summary endpoint returns end-customer wallet addresses.** The dashboard is the only surface allowed to opt in (`includeOwnerAddresses`), per threat model EARN-028; the response is `private, no-store` and project-scoped.
- **An absent `earned` is not `$0`.** Earnings that could not be read render as a dash, matching the unavailable-position rule everywhere else.
- **The per-owner positions proxy has no production caller yet.** `fetchEarnExternalWalletPositions` is exported for the planned wallet drill-down ("kept at the strict dashboard boundary"); the route is live, session-gated, base58-validated and page-limited, so leaving it reachable is safe.
